## 一、测试金字塔

### 1.1 三层测试结构

```
        ╱╲
       ╱E2E╲         65 用例，15 场景
      ╱──────╲        端到端验证（需 LLM + 沙箱）
     ╱        ╲       就像"整栋楼通电试运行"
    ╱ 集成测试  ╲      40 用例
   ╱            ╲     Hook 链路 + 安全链路
  ╱──────────────╲    就像"每层楼结构验收"
 ╱    单元测试     ╲   188 用例
╱__________________╲  纯逻辑，无外部依赖
                      就像"查每块砖的强度"
```

### 1.2 各层职责与对比

| 层级 | 用例数 | 运行速度 | 依赖 | 验证内容 | 跑一次成本 |
|------|--------|---------|------|---------|-----------|
| 单元 | 188 | <10s | 无 | 函数逻辑正确性 | 几乎为 0 |
| 集成 | 40 | ~30s | Langfuse | Hook 链路协作 | 需要起 Langfuse |
| E2E | 65 | ~10min | LLM + 沙箱 + pgvector | 完整用户体验 | 真实消耗 token |

### 1.3 为什么"多写单元测试，少写 E2E"？

```
❌ 错误策略：依赖 E2E 验证一切
  - 每次跑 E2E 要 10 分钟，反馈太慢
  - 改一行代码要等 10 分钟才知道有没有破坏什么
  - LLM 输出有不确定性，E2E 可能时过时不过
  - 一次 E2E 跑可能消耗几美元的 token
  - 失败时很难定位"是哪个组件的问题"

✅ 正确策略：金字塔结构
  - 大量单元测试覆盖函数级逻辑 → 改一行立即知道对错（10 秒）
  - 中等集成测试覆盖模块协作 → 30 秒发现链路问题
  - 少量 E2E 验证完整体验 → 上线前才跑
  - 这就是"建筑质量验收"的思路：
    砖的强度（单元）→ 楼层结构（集成）→ 整楼试运行（E2E）
```

### 1.4 pytest 框架概念（小白先看这里）

| 概念 | 含义 | 例子 |
|------|------|------|
| `pytest` | Python 最流行的测试框架 | `pytest tests/` 运行所有测试 |
| 测试函数 | 以 `test_` 开头的函数 | `def test_basic_search():` |
| 断言（assert） | 验证预期是否成立 | `assert len(replies) > 0` |
| fixture | 测试前置准备（setUp） | `@pytest.fixture def client(): ...` |
| marker（标记） | 给测试打标签，便于筛选 | `@pytest.mark.e2e` |
| conftest.py | 共享 fixture 的文件 | `tests/conftest.py` 全局生效 |

```python
"""SandboxGuard 单元测试。"""
# 这个文件验证沙箱守卫的检测能力，包括路径穿越、危险命令、Shell 注入、Prompt 注入

import pytest
from shared_hooks.sandbox_guard import SandboxGuard, _normalize
from xiaopaw.hook_framework.registry import (
    DenyReason,         # deny 原因枚举（如 sandbox_violation、prompt_injection）
    GuardrailDeny,      # deny 异常类
    HookContext,        # 上下文对象（携带事件类型、工具名、输入等）
    EventType,          # 事件类型枚举
)


class TestPathTraversal:
    """路径穿越检测测试。"""
    # 路径穿越（Path Traversal）：攻击者用 ../ 跳出限制目录

    def setup_method(self):
        """每个测试方法运行前调用一次（pytest 风格的 setUp）。"""
        self.guard = SandboxGuard()  # 创建一个全新的 guard 实例，避免测试间污染

    def test_basic_path_traversal(self):
        """检测基本路径穿越。"""
        # ━━━ arrange（准备）：构造输入 ━━━
        ctx = HookContext(
            event_type=EventType.BEFORE_TOOL_CALL,    # 事件类型：工具调用前
            tool_name="skill_loader",                 # 工具名：技能加载器
            tool_input={"content": "../../etc/passwd"},  # 攻击 payload：跳到系统密码文件
        )

        # ━━━ act（执行）+ assert（断言）━━━
        # pytest.raises 期望抛出 GuardrailDeny 异常
        # 如果没抛异常 → 测试失败
        # 如果抛了其他异常 → 测试也失败
        with pytest.raises(GuardrailDeny) as exc_info:
            self.guard.before_tool_handler(ctx)       # 调用被测函数

        # ━━━ assert（断言）：验证异常的原因码 ━━━
        # exc_info.value 拿到抛出的异常对象
        # reason_code 应该是 "sandbox_violation"（沙箱违规）
        assert exc_info.value.reason_code == "sandbox_violation"

    def test_url_encoded_traversal(self):
        """检测 URL 编码的路径穿越。"""
        # ━━━ arrange ━━━
        ctx = HookContext(
            event_type=EventType.BEFORE_TOOL_CALL,
            tool_name="skill_loader",
            # %2E%2E%2F 是 ../ 的 URL 编码，攻击者常用这种手法绕过简单字符串匹配
            tool_input={"content": "%2E%2E%2F%2E%2E%2Fetc%2Fpasswd"},
        )

        # ━━━ act + assert ━━━
        with pytest.raises(GuardrailDeny):
            self.guard.before_tool_handler(ctx)
            # 只要抛了 GuardrailDeny 就算通过，不验证具体原因码

    def test_double_encoded_traversal(self):
        """检测双重 URL 编码。"""
        # ━━━ arrange ━━━
        ctx = HookContext(
            event_type=EventType.BEFORE_TOOL_CALL,
            tool_name="skill_loader",
            # %25 是 % 的 URL 编码，所以 %252E 是 %2E 的双重编码
            # 这是一种更隐蔽的绕过技巧
            tool_input={"content": "%252E%252E%252F"},
        )

        # ━━━ act + assert ━━━
        with pytest.raises(GuardrailDeny):
            self.guard.before_tool_handler(ctx)

    def test_unicode_fullwidth_traversal(self):
        """检测全角字符路径穿越。"""
        # ━━━ arrange ━━━
        ctx = HookContext(
            event_type=EventType.BEFORE_TOOL_CALL,
            tool_name="skill_loader",
            # ．．／ 是 ../ 的全角版本，攻击者利用 Unicode 形态绕过
            tool_input={"content": "．．／etc／passwd"},
        )

        # ━━━ act + assert ━━━
        with pytest.raises(GuardrailDeny):
            self.guard.before_tool_handler(ctx)
```

```python
# tests/unit/hook_framework/test_hook_registry.py
"""HookRegistry 单元测试。"""
# 这个文件验证注册中心的两种分发机制：dispatch（不阻断）和 dispatch_gate（可阻断）

import pytest
from xiaopaw.hook_framework.registry import (
    EventType,
    GuardrailDeny,
    HookContext,
    HookRegistry,
)


class TestDispatch:
    """dispatch（报警器模式）测试。"""
    # dispatch 模式：所有 handler 都执行，异常被吞掉

    def test_all_handlers_called(self):
        """所有 handler 都会被调用。"""
        # ━━━ arrange ━━━
        registry = HookRegistry()
        calls = []  # 用列表记录调用顺序

        def handler1(ctx):
            calls.append("handler1")  # 模拟：往列表里追加字符串

        def handler2(ctx):
            calls.append("handler2")

        registry.register(EventType.BEFORE_TURN, handler1)  # 注册第 1 个
        registry.register(EventType.BEFORE_TURN, handler2)  # 注册第 2 个

        # ━━━ act ━━━
        registry.dispatch(EventType.BEFORE_TURN, HookContext(
            event_type=EventType.BEFORE_TURN
        ))

        # ━━━ assert ━━━
        # 调用顺序应该和注册顺序一致
        assert calls == ["handler1", "handler2"]

    def test_exception_swallowed(self):
        """handler 异常被吞掉，不影响后续。"""
        # ━━━ arrange ━━━
        registry = HookRegistry()
        calls = []

        def bad_handler(ctx):
            raise ValueError("oops")  # 这个 handler 会抛异常

        def good_handler(ctx):
            calls.append("called")  # 这个 handler 应该照常执行

        registry.register(EventType.BEFORE_TURN, bad_handler)  # 先注册坏的
        registry.register(EventType.BEFORE_TURN, good_handler)  # 再注册好的

        # ━━━ act ━━━
        # dispatch 应该不抛异常（异常被吞掉）
        registry.dispatch(EventType.BEFORE_TURN, HookContext(
            event_type=EventType.BEFORE_TURN
        ))

        # ━━━ assert ━━━
        # 即使 bad_handler 崩了，good_handler 仍然被调用
        assert calls == ["called"]


class TestDispatchGate:
    """dispatch_gate（保险丝模式）测试。"""
    # dispatch_gate 模式：handler 抛 GuardrailDeny 会中止整个链路

    def test_guardrail_deny_propagates(self):
        """GuardrailDeny 能穿透。"""
        # ━━━ arrange ━━━
        registry = HookRegistry()

        def deny_handler(ctx):
            raise GuardrailDeny("sandbox_violation", "test")  # 模拟 deny

        registry.register(EventType.BEFORE_TOOL_CALL, deny_handler)

        # ━━━ act + assert ━━━
        # dispatch_gate 应该把异常往上抛（穿透到业务代码）
        with pytest.raises(GuardrailDeny):
            registry.dispatch_gate(EventType.BEFORE_TOOL_CALL, HookContext(
                event_type=EventType.BEFORE_TOOL_CALL
            ))

    def test_fail_closed(self):
        """fail_closed=True 时，handler 崩溃转成 deny。"""
        # ━━━ arrange ━━━
        registry = HookRegistry()

        def crash_handler(ctx):
            raise RuntimeError("handler crashed")  # 模拟 handler 内部崩溃（非 GuardrailDeny）

        # 注册时标记 fail_closed=True
        registry.register(
            EventType.BEFORE_TOOL_CALL,
            crash_handler,
            fail_closed=True,  # ★ 关键：崩溃转 deny
        )

        # ━━━ act + assert ━━━
        # 即使抛的是 RuntimeError（非 GuardrailDeny），
        # fail_closed=True 会把它转成 GuardrailDeny 抛出
        with pytest.raises(GuardrailDeny):
            registry.dispatch_gate(EventType.BEFORE_TOOL_CALL, HookContext(
                event_type=EventType.BEFORE_TOOL_CALL
            ))

    def test_first_deny_stops_chain(self):
        """首次 deny 立即中止链路。"""
        # ━━━ arrange ━━━
        registry = HookRegistry()
        calls = []

        def first_handler(ctx):
            calls.append("first")
            raise GuardrailDeny("sandbox_violation", "deny")  # 第一个就 deny

        def second_handler(ctx):
            calls.append("second")  # 这一行不应该被执行到

        registry.register(EventType.BEFORE_TOOL_CALL, first_handler)
        registry.register(EventType.BEFORE_TOOL_CALL, second_handler)

        # ━━━ act + assert ━━━
        with pytest.raises(GuardrailDeny):
            registry.dispatch_gate(EventType.BEFORE_TOOL_CALL, HookContext(
                event_type=EventType.BEFORE_TOOL_CALL
            ))

        # 验证 second 没被调用
        assert calls == ["first"]  # second 没被调用
```

```python
# tests/integration/test_hook_chain.py
"""Hook 链路集成测试 —— 验证多个策略协作。"""
# 这个文件验证"观测层先于策略层执行"这个核心约束

import pytest
from xiaopaw.hook_framework.registry import HookRegistry, HookContext, EventType
from shared_hooks.sandbox_guard import SandboxGuard
from shared_hooks.cost_guard import CostGuard
from shared_hooks.loop_detector import LoopDetector


class TestHookChain:
    """多策略链路测试。"""

    def test_observation_before_strategy(self):
        """观测层先于策略层执行。"""
        # ━━━ arrange ━━━
        registry = HookRegistry()
        execution_order = []  # 记录执行顺序

        # 观测层 handler
        def log_handler(ctx):
            execution_order.append("log")

        # 策略层 handler
        def guard_handler(ctx):
            execution_order.append("guard")

        # 先注册观测层（注册顺序 = 执行顺序）
        registry.register(EventType.BEFORE_TOOL_CALL, log_handler, fail_closed=False)

        # 再注册策略层
        registry.register(EventType.BEFORE_TOOL_CALL, guard_handler, fail_closed=False)

        # ━━━ act ━━━
        registry.dispatch(EventType.BEFORE_TOOL_CALL, HookContext(
            event_type=EventType.BEFORE_TOOL_CALL,
            tool_input={},
        ))

        # ━━━ assert ━━━
        # 验证 log 在 guard 之前执行
        assert execution_order == ["log", "guard"]


class TestSecurityChain:
    """安全链路测试。"""

    def test_sandbox_then_permission(self):
        """sandbox_guard 先执行，deny 后 permission_gate 不执行。"""
        # ━━━ arrange ━━━
        registry = HookRegistry()
        guard = SandboxGuard()
        permission_calls = []  # 用来记录 permission_gate 是否被调用

        def permission_handler(ctx):
            permission_calls.append("called")

        # 注册顺序：sandbox → permission
        registry.register(
            EventType.BEFORE_TOOL_CALL,
            guard.before_tool_handler,   # sandbox 的 handler
            fail_closed=True,            # ★ 关键：fail_closed=True
        )
        registry.register(
            EventType.BEFORE_TOOL_CALL,
            permission_handler,           # permission 的 handler
            fail_closed=False,
        )

        # ━━━ act ━━━
        # 触发 sandbox_guard deny（rm -rf / 是危险命令）
        with pytest.raises(GuardrailDeny):
            registry.dispatch_gate(EventType.BEFORE_TOOL_CALL, HookContext(
                event_type=EventType.BEFORE_TOOL_CALL,
                tool_name="skill_loader",
                tool_input={"content": "rm -rf /"},
            ))

        # ━━━ assert ━━━
        # permission_gate 不应该被调用（因为 sandbox 已经 deny 中止了链路）
        assert permission_calls == []
```

## 六、测试配置

### 6.1 conftest.py（fixture 全局共享）

```python
# tests/conftest.py
"""全局测试配置。"""
# 这个文件里的 fixture 所有测试都能用
# pytest 启动时会自动加载 conftest.py

import pytest
from pathlib import Path


@pytest.fixture
def tmp_workspace(tmp_path):
    """创建临时工作区目录。
    为什么用 fixture：
      1. 多个测试都需要"工作区"，避免重复代码
      2. tmp_path 是 pytest 内置 fixture，每次测试自动清理
      3. fixture 可以做 setup + yield + teardown（清理）
    """
    workspace = tmp_path / "workspace"  # tmp_path 是 pytest 提供的临时目录
    workspace.mkdir()                   # 创建目录

    # 复制记忆四件套模板（让测试更接近真实环境）
    import shutil
    init_dir = Path("workspace-init")   # 模板目录
    if init_dir.exists():
        for f in init_dir.iterdir():
            if f.is_file():
                shutil.copy2(f, workspace / f.name)  # 复制文件

    return workspace  # 返回给测试使用


@pytest.fixture
def hook_registry():
    """创建空的 HookRegistry。
    用途：每个测试方法都拿到一个全新的 registry，避免互相污染。"""
    from xiaopaw.hook_framework.registry import HookRegistry
    return HookRegistry()


@pytest.fixture
def sample_hook_context():
    """创建示例 HookContext。
    用途：测试需要"现成的上下文"，避免每次手写一堆字段。"""
    from xiaopaw.hook_framework.registry import EventType, HookContext
    return HookContext(
        event_type=EventType.BEFORE_TOOL_CALL,
        tool_name="skill_loader",
        tool_input={"skill_name": "baidu_search"},
        session_id="test-session",
    )
```

### 6.2 为什么用 fixture？（深入理解）

| 不用 fixture | 用 fixture |
|-------------|-----------|
| 每个测试方法手写 setup 代码 | 复用一份 setup |
| 测试方法之间容易污染 | fixture 默认每个测试独立实例 |
| 清理代码到处散落 | yield 前后自动 setup/teardown |
| 难以共享（要在每个文件里 import） | conftest.py 全局自动加载 |

## 八、设计优势与局限性

### 优势

1. **分层测试**：单元/集成/E2E 各有职责，按需运行

1. **E2E 依赖多**：需要 LLM + 沙箱 + pgvector 都在线

3. **LLM 不确定性**：E2E 断言可能不稳定（同样输入 LLM 可能给不同输出）

## ❓ 常见问题

### Q1：测试报 `ModuleNotFoundError: No module named 'shared_hooks'`？
**A**：pytest 找不到模块路径。**修复**：
1. 确认在项目根目录运行（`pwd` 应该是 `xiaopaw-v2/`）
2. 检查 `pyproject.toml` 或 `setup.py` 是否配置了 package
3. 或者设置 PYTHONPATH：`export PYTHONPATH=.`（Linux/Mac）/ `set PYTHONPATH=.`（Windows）

### Q2：`pytest.raises(GuardrailDeny)` 没抛异常，测试失败？
**A**：可能原因：
1. 被测函数的逻辑没触发 deny（输入不够"恶意"）
2. handler 注册时没设 `fail_closed=True`，崩溃没被转成 deny
3. 异常类型不对（应该是 GuardrailDeny，但你抛了别的）
**排查**：去掉 `pytest.raises`，直接调用，看实际抛什么异常。

### Q3：E2E 测试一直卡住不动？
**A**：E2E 需要 LLM + 沙箱在线。**排查**：
```bash
# 检查 XiaoPaw 是否启动
curl http://127.0.0.1:9090/metrics

# 检查沙箱是否在线
curl -s -X POST http://127.0.0.1:8030/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'

# 检查 Langfuse 是否在线
curl http://127.0.0.1:3000/api/public/health
```
任何一个不通，E2E 就会卡住。建议加超时：`pytest --timeout=120`。

### Q4：异步测试报 `RuntimeError: Event loop is closed`？
**A**：pytest-asyncio 的常见问题。**修复**：
1. 确认安装了 `pytest-asyncio`
2. 在 `pyproject.toml` 配置：
```toml
[tool.pytest.ini_options]
asyncio_mode = "auto"
```
3. 测试函数用 `async def` 而不是 `def`

### Q5：测试覆盖率怎么提高？
**A**：先跑 `pytest --cov=xiaopaw --cov-report=html`，看哪些行红色（未覆盖）：
- 分支没走到：补 if/else 两侧的测试
- 异常路径没走：构造异常输入
- 工具函数没测：加单元测试
- **不建议**：为了覆盖率而写"无意义的测试"（如 `assert True`）

### Q6：fixture 和 setup_method 有什么区别？
**A**：
- `setup_method`：pytest 经典写法，每个测试方法前调用，没有返回值
- `fixture`：现代写法，可以有返回值，可以注入到测试函数参数里
- 推荐用 fixture，更灵活、可复用

### Q7：怎么只跑某个测试方法？
**A**：用 `::` 指定：
```bash
# 只跑某个类的某个方法
pytest tests/unit/shared_hooks/test_sandbox_guard.py::TestPathTraversal::test_basic_path_traversal -v

# 只跑某个类
pytest tests/unit/shared_hooks/test_sandbox_guard.py::TestPathTraversal -v

# 只跑某个文件
pytest tests/unit/shared_hooks/test_sandbox_guard.py -v
```

## 🔧 调试技巧

### 技巧 1：用 `-s` 看 print 输出

默认 pytest 会捕获 print 输出。加 `-s` 可以显示：
```bash
pytest tests/unit/ -v -s
```
适合临时加 `print("DEBUG:", ctx)` 调试。

### 技巧 2：用 `--pdb` 进入调试器

测试失败时自动进入 pdb：
```bash
pytest tests/unit/ -v --pdb
```
失败后可以在交互式调试器里查看变量、单步执行。

### 技巧 3：用 `--lf` 只跑上次失败的

```bash
# 第一次跑全部
pytest tests/unit/

# 只跑失败的
pytest --lf
```
`--lf` 是 `--last-failed` 的简写。

### 技巧 4：用 `--ff` 先跑失败的

```bash
pytest --ff
```
`--ff` 是 `--failed-first`，先跑失败的，再跑其他的。适合"改完 bug 想立刻看结果"。

### 技巧 5：用 `-x` 遇到第一个失败就停

```bash
pytest tests/unit/ -x
```
适合快速定位"哪里先坏"。一次跑 100 个测试，前 50 个过了，第 51 个失败就停，不用等全部跑完。

### 技巧 6：用 `assert` 加消息

```python
assert len(replies) > 0, f"应该有回复，但收到 {replies}"
```
失败时消息更清晰，知道是空列表还是其他情况。

### 技巧 7：用 `pytest --collect-only` 看测试列表

```bash
pytest --collect-only
```
列出所有测试，确认 marker 和命名是否符合预期。
