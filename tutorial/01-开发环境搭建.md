> 📖 **概念小课堂：什么是"运行时"（Runtime）？**
>
> 你写的 Python 代码是文本，电脑看不懂文本。需要一个"翻译器"把它变成机器能跑的指令——这个翻译器就是 Python 运行时（也叫 Python 解释器）。装 Python 就是装这个翻译器。

### 1.1 安装 Python 3.11+

> 📖 **概念小课堂：为什么要 3.11+？**
>
> Python 3.11 之后异步性能大幅提升，类型提示也更完善。XiaoPaw 用了大量 async/await 语法，老版本 Python 跑不动。

#### Windows（PowerShell）

**做什么**：下载安装包并安装 Python。
**怎么做**：

1. 访问 https://www.python.org/downloads/ 下载最新 Python 3.11+ 安装包（exe 文件）
2. 双击运行安装程序
3. **关键步骤**：勾选 "Add Python to PATH"（把 Python 加进系统路径）
4. 点击 "Install Now" 等待安装完成

**验证**：

```powershell
python --version
# ↑ python 是 Python 解释器的命令
# ↑ --version 是它的参数（注意是两个减号），作用是"显示版本号然后退出"
# 期望输出：Python 3.11.x 或更高
```

✅ **验证成功**：输出形如 `Python 3.11.9`
❌ **常见错误**：报"python 不是内部或外部命令" → 安装时没勾"Add to PATH"，重装并勾上。

#### macOS（Homebrew）

```bash
brew install python@3.11
# ↑ brew 是 macOS 包管理器（要先装 Homebrew）
# ↑ install 是动作
# ↑ python@3.11 指定要装 Python 3.11 版本
python3.11 --version
# ↑ 注意 mac 上可能是 python3.11 不是 python
```

✅ **验证成功**：输出 `Python 3.11.x`
❌ **常见错误**：`brew: command not found` → 先装 Homebrew：`/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"`

#### Linux（Ubuntu/Debian）

```bash
sudo apt update
# ↑ sudo = 以管理员权限运行
# ↑ apt = Ubuntu 的包管理器（类似 mac 的 brew）
# ↑ update = 更新软件源列表（不实际安装，只是刷新可用清单）

sudo apt install python3.11 python3.11-venv python3.11-dev
# ↑ install = 安装
# ↑ python3.11 主包
# ↑ python3.11-venv 虚拟环境模块（关键！没这个建不了 venv）
# ↑ python3.11-dev 开发头文件（编译某些包时需要）

python3.11 --version
# ↑ 验证安装
```

✅ **验证成功**：输出 `Python 3.11.x`

### 1.2 安装 Docker

> 📖 **概念小课堂：Docker 是什么？**
>
> 想象你买了一个家具，要送回家。普通快递：把家具拆散装箱，到家再装——可能装错。Docker 模式：整个房间连同家具一起打包送过来，开门即用。Docker 容器就是"打包好的房间"——里面装着运行环境（操作系统 + 库 + 程序），换台电脑也能原样跑。
>
> XiaoPaw 用 Docker 跑沙箱——AI 写的代码在容器里执行，崩了也不影响你的电脑。

#### Windows

**做什么**：装 Docker Desktop。
**怎么做**：

1. 访问 https://www.docker.com/get-started 下载 Docker Desktop for Windows
2. 双击安装，全程下一步
3. 安装完启动 Docker Desktop（系统托盘会出现鲸鱼图标）

> **如果失败了怎么办**：Win10/11 家庭版要先装 WSL2（Windows Subsystem for Linux）。安装 Docker Desktop 时它会提示，按提示装即可。装完重启电脑。

#### macOS

```bash
brew install --cask docker
# ↑ brew 是 Homebrew
# ↑ install --cask 表示装 GUI 应用（不是命令行工具）
# ↑ docker 是应用名

# 安装后启动 Docker.app（在应用程序里找到 Docker 双击）
```

#### Linux（Ubuntu）

```bash
curl -fsSL https://get.docker.com | sudo sh
# ↑ curl 是命令行下载工具
# ↑ -f 失败时不输出 HTML 错误页
# ↑ -s 静默模式（不显示进度条）
# ↑ -S 即使静默也显示错误
# ↑ -L 跟随重定向
# ↑ https://get.docker.com 是 Docker 官方安装脚本
# ↑ | 管道符：把下载的脚本输出送给后面的命令
# ↑ sudo sh 以管理员身份执行脚本

sudo usermod -aG docker $USER
# ↑ usermod 修改用户属性
# ↑ -aG 把用户加入 docker 组（这样不用每次都 sudo）
# ↑ $USER 当前用户名（环境变量）

# 重新登录后生效（注销重新登，或者 newgrp docker 立即生效）
```

**验证**：

```bash
docker --version
# ↑ 应输出 Docker version 24.x 或更高

docker compose version
# ↑ 验证 compose 插件（管理多容器编排的工具）

docker run hello-world
# ↑ 跑一个测试容器
# ↑ 如果看到 "Hello from Docker!" 说明 Docker 能正常工作
```

✅ **验证成功**：三条命令都有正常输出
❌ **常见错误**：
- `Cannot connect to the Docker daemon` → Docker 服务没启动，去托盘点鲸鱼图标启动
- `permission denied` → Linux 用户没加进 docker 组，重新执行 `sudo usermod -aG docker $USER` 然后注销重登

### 1.3 获取 DashScope API Key

> 📖 **概念小课堂：什么是 API Key？**
>
> API Key 像你的门禁卡——证明"我是合法用户"。每次调用阿里云大模型，都要带这张卡，否则阿里云拒绝服务。**这张卡不能泄露**——别人拿到能花你账户里的钱。

**做什么**：注册阿里云账号，开通 DashScope，生成 API Key。
**怎么做**：

1. 访问 https://dashscope.aliyun.com/ 用支付宝/淘宝账号登录
2. 开通服务（新用户有免费额度，100 万 token 够你学很久）
3. 进控制台 → API-KEY 管理 → 创建新的 API-KEY
4. 复制 Key，格式形如 `sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`

**设置环境变量**（后续所有命令都依赖它）：

```bash
# Windows PowerShell（注意：用 $env:，不是 export）
$env:QWEN_API_KEY = "sk-你的key"
# ↑ $env: 是 PowerShell 设置环境变量的前缀
# ↑ QWEN_API_KEY 是变量名（项目代码会读这个名字）
# ↑ = 后面是值，要带引号

# macOS / Linux
export QWEN_API_KEY="sk-你的key"
# ↑ export 是 Linux/Mac 设置环境变量的命令
# ↑ 注意：这样设只对当前终端有效，关掉终端就没了
# ↑ 永久生效要写进 ~/.bashrc 或 ~/.zshrc
```

> 🔧 **调试技巧**：永久设置环境变量
> - Windows：系统属性 → 高级 → 环境变量 → 新建用户变量
> - macOS/Linux：`echo 'export QWEN_API_KEY="sk-xxx"' >> ~/.zshrc && source ~/.zshrc`

## 二、项目初始化

### 2.1 创建项目目录

```bash
mkdir xiaopaw-v2
# ↑ mkdir = make directory 创建目录
# ↑ xiaopaw-v2 是目录名

cd xiaopaw-v2
# ↑ cd = change directory 切换到这个目录
# ↑ 之后所有命令都在这个目录里执行
```

### 2.2 创建虚拟环境

> 📖 **概念小课堂：什么是"虚拟环境"？**
>
> 想象你有多个 Python 项目：A 项目要 Django 2.0，B 项目要 Django 4.0。如果都装在系统 Python 里，肯定打架。虚拟环境就是给每个项目一个"独立小房间"——里面装自己需要的包，互不打扰。
>
> XiaoPaw 装在 `.venv` 这个虚拟环境里，跟你电脑上的其他 Python 项目完全隔离。

```bash
# 创建虚拟环境
python -m venv .venv
# ↑ python -m 表示"以模块方式运行"
# ↑ venv 是 Python 内置的虚拟环境模块
# ↑ .venv 是目录名（约定俗成用 .venv，前面的点表示隐藏目录）
```

```text 逐行解释
python    → 调用 Python 解释器
-m        → "以模块方式运行"，告诉 Python "我要运行一个模块而不是脚本"
venv      → 模块名（Python 内置的虚拟环境工具）
.venv     → venv 模块的参数，指定虚拟环境放在哪个目录

效果：在当前目录下创建 .venv/ 子目录，里面有独立的 Python 解释器和包管理器
```

**激活虚拟环境**（每次打开新终端都要做这一步）：

```bash
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# ↑ .venv\Scripts\ 是虚拟环境里的脚本目录
# ↑ Activate.ps1 是 PowerShell 激活脚本

# macOS / Linux:
source .venv/bin/activate
# ↑ source 在当前 shell 中执行脚本（不是开子进程）
# ↑ .venv/bin/activate 是激活脚本路径
```

**验证激活成功**：

```bash
where python  # Windows
# ↑ where 显示 python 命令的完整路径
# 激活后应该显示 .venv\Scripts\python.exe

which python   # macOS / Linux
# ↑ which 同上
```

✅ **验证成功**：命令提示符前面出现 `(.venv)`，且 `where python` 显示 `.venv` 路径
❌ **常见错误**：
- `Activate.ps1 cannot be loaded because running scripts is disabled` → PowerShell 默认禁脚本，执行 `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` 一次即可
- 装包时报 `Permission denied` → 多半是没激活虚拟环境，pip 装到系统目录被拒

> 🔧 **调试技巧**：每次新开终端，提示符前没有 `(.venv)`，说明虚拟环境没激活。重跑激活命令即可。如果总是忘记，可以在项目根目录加个 `.envrc`（配合 direnv 工具）自动激活。

### 2.3 创建 pyproject.toml

> 📖 **概念小课堂：什么是 pyproject.toml？**
>
> `.toml` 是一种配置文件格式（Tom's Obvious, Minimal Language）。`pyproject.toml` 是 Python 项目标准配置文件——声明项目名、版本、依赖、构建方式。可以理解为"项目的身份证 + 采购清单"。

这是 Python 项目的标准配置文件，声明项目元数据和依赖：

```toml
[project]
# ↑ [project] 是一个 TOML 表（section），下面是项目基本信息
name = "xiaopaw-v2"                        # 项目名
version = "3.0.0"                          # 版本号
description = "XiaoPaw v3 — Feishu local AI work assistant with Hook framework"
requires-python = ">=3.11"                 # 要求 Python 3.11 或更高
dependencies = [
    # ↑ 核心依赖列表（必装的包）
    "pyyaml>=6.0",       # YAML 文件解析（读 config.yaml 用）
    "pydantic>=2.0",     # 配置校验与数据模型（启动时检查配置对不对）
    "aiohttp>=3.9",      # 异步 HTTP 服务（TestAPI 用它起 HTTP 服务）
    "requests>=2.31",    # 同步 HTTP 客户端（调飞书 API 用）
    "crewai>=1.9.3",     # Agent 编排框架（项目核心）
    "lark-oapi>=1.3",    # 飞书 SDK（连飞书 WebSocket 用）
]

[project.optional-dependencies]
# ↑ 可选依赖（按需装，不装也能跑基础功能）
# 完整功能依赖（向量搜索、可观测性等）
full = [
    "psycopg2-binary>=2.9",  # PostgreSQL 驱动（连 pgvector 用）
    "openai>=1.0",            # OpenAI SDK（DashScope 兼容 OpenAI 协议）
    "croniter>=2.0",          # cron 表达式解析（定时任务用）
    "filelock>=3.13",         # 文件锁（多进程并发安全写文件）
    "prometheus_client>=0.20", # 指标暴露（/metrics 端点）
    "cachetools>=5.3",        # 缓存工具（短期记忆缓存）
    "langfuse>=4.0",          # 可观测性平台（全链路追踪）
]

# 开发工具依赖
dev = [
    "pytest>=8.0",            # 测试框架
    "pytest-cov>=5.0",        # 测试覆盖率统计
    "pytest-asyncio>=0.24",   # 异步测试支持（测 asyncio 代码用）
    "pytest-timeout>=2.3",    # 测试超时控制（防卡死）
    "ruff>=0.4",              # 代码格式化与检查（替代 black + flake8）
]

[tool.pytest.ini_options]
# ↑ pytest 配置
testpaths = ["tests"]    # 测试文件目录
asyncio_mode = "auto"   # 自动识别异步测试函数
timeout = 600            # 单个测试最多跑 600 秒

[tool.coverage.run]
# ↑ 覆盖率统计配置
source = ["xiaopaw", "shared_hooks"]  # 统计这两个目录的覆盖率
omit = ["tests/*"]                   # 不统计测试代码本身
```

```text 逐行解释
[project]
    这是 PEP 621 标准定义的项目元数据段
name / version / description
    对应 PyPI 上的项目展示信息
requires-python = ">=3.11"
    告诉 pip：装这个项目前，先检查 Python 版本必须 ≥ 3.11
dependencies = [...]
    核心依赖：pip install 时会自动装这些
    每个包后面跟的 >=X.Y 是最低版本要求
[project.optional-dependencies]
    可选依赖：用 pip install ".[full,dev]" 这种语法按需装
    full → 完整功能；dev → 开发工具
[tool.pytest.ini_options]
    pytest 的配置，让 pytest 知道去哪找测试、怎么跑
```

> 💡 **实际场景**：开发时你想用全部功能 + 测试工具，就装 `pip install -e ".[full,dev]"`。生产部署只装核心：`pip install -e "."`（不加方括号）。

### 2.4 安装依赖

```bash
# 安装核心依赖 + 完整功能依赖 + 开发工具
pip install -e ".[full,dev]"
# ↑ pip 是 Python 包管理器
# ↑ install 安装
# ↑ -e "editable" 模式：把项目装成"可编辑"的，改代码不用重装
# ↑ "." 当前目录（pip 会读 pyproject.toml）
# ↑ [full,dev] 装可选依赖里的 full 和 dev 两组
```

```text 逐行解释
pip         Python 包管理器命令
install     子命令：安装
-e          editable 的缩写，"可编辑模式"
            → 不复制代码到 site-packages，而是建一个软链接
            → 改了源码立即生效，不用重新 pip install
".[full,dev]"
    .       → 当前目录（pip 找当前目录的 pyproject.toml）
    [full,dev] → 装 optional-dependencies 里的 full 和 dev 两组
```

> 🔧 **调试技巧**：如果 `pip install` 超时（国内网络问题），换清华源：
> ```bash
> pip install -e ".[full,dev]" -i https://pypi.tuna.tsinghua.edu.cn/simple
> ```
> 永久换源：`pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`

**各依赖包的作用解释**：

| 包名 | 作用 | 核心函数/类 | 选择理由 |
|------|------|------------|---------|
| `pyyaml` | 解析 YAML 配置 | `yaml.safe_load()` | 配置文件标准格式 |
| `pydantic` | 数据校验 | `BaseModel`, `Field()` | 类型安全，启动即校验 |
| `aiohttp` | 异步 HTTP | `web.Application` | TestAPI 服务 |
| `crewai` | Agent 框架 | `Agent`, `Crew`, `Task` | 两层 Agent 架构 |
| `lark-oapi` | 飞书 SDK | `Client.builder()` | WebSocket 长连接 |
| `psycopg2-binary` | PostgreSQL 驱动 | `connect()` | 向量记忆存储 |
| `openai` | LLM 调用 | `OpenAI()` | DashScope 兼容 OpenAI 协议 |
| `langfuse` | 追踪平台 | `Langfuse()` | 全链路可观测 |

> 📖 **概念小课堂：为什么 `-binary` 后缀？**
>
> `psycopg2` 是源码包，安装时要本地编译 C 代码（要装编译器）。`psycopg2-binary` 是预编译包，装上就能用，不需要编译器。开发环境用 binary 版本省事，生产环境建议用源码版（更稳定）。

## 三、配置文件准备

### 3.1 创建 config.yaml

> 📖 **概念小课堂：为什么用 YAML 不用 JSON？**
>
> YAML 支持注释（`#`），JSON 不支持。配置文件没人写注释看不懂，所以选 YAML。YAML 还支持多行字符串、引用等，可读性更好。

```yaml
# config.yaml — XiaoPaw 主配置文件
# ↑ 文件第一行写注释说明文件用途，是好习惯

# 工作区目录（用户记忆文件存放处）
workspace: "data/workspace"
# ↑ 用户数据放这里（对话历史、记忆文件）
data_dir: "data"
# ↑ 通用数据目录

# 飞书应用配置
feishu:
  app_id: "${FEISHU_APP_ID}"        # ${ENV_VAR} 引用环境变量
  app_secret: "${FEISHU_APP_SECRET}" # 密钥不放配置文件，从环境变量读
  allowed_chats: []                  # 允许的群聊 ID（空 = 全部允许）

# Agent 配置
agent:
  model: "qwen3-max"                 # 主 LLM 模型名
  max_iter: 50                      # 单轮最大迭代次数（防烧钱）
  max_input_tokens: 30000           # 输入 token 上限（防超长）

# 沙箱配置
sandbox:
  url: "http://localhost:8030/mcp"  # AIO-Sandbox MCP 地址
  timeout_s: 120                    # 沙箱调用超时（秒）

# 记忆配置
memory:
  db_dsn: ""                        # PostgreSQL 连接串（向量搜索用，空 = 不用）
  hard_limit_lines: 250             # memory.md 最大行数（防膨胀）
  context_window_tokens: 32000      # 上下文窗口大小

# 会话配置
session:
  max_active_sessions: 1000         # 同时活跃的会话上限
  max_history_turns: 20             # 保留最近 20 轮对话

# 开发调试配置
debug:
  enable_test_api: true            # 启用 TestAPI（开发模式才开）
  test_api_host: "127.0.0.1"        # 只本机访问
  test_api_port: 9090               # TestAPI 端口
  test_api_token: "dev-token-change-me"  # 简单 token，生产要换

# 可观测性配置
observability:
```

### 3.2 理解环境变量引用

配置文件中 `${ENV_VAR}` 语法会在运行时被环境变量替换：

```python
# config.yaml:
#   app_id: "${FEISHU_APP_ID}"
#
# 运行时：
#   如果设置了 export FEISHU_APP_ID="cli_xxx"
#   则 cfg.feishu.app_id = "cli_xxx"
#
# 如果没设环境变量，则 app_id 是字面量 "${FEISHU_APP_ID}"
# 项目代码会做替换：os.environ.get("FEISHU_APP_ID", default)

# 这种设计让敏感信息（密码、Key）不进入代码仓库
# 团队协作时，每个人用自己的 .env 文件，互不干扰
```

> 💡 **实际场景**：你把项目传到 GitHub，别人 clone 下来。如果密钥写在 config.yaml 里，所有人都看到你的密钥了——别人用你的额度，账单算你头上。用环境变量隔离，每个人用自己的 key。

## 四、启动沙箱服务

### 4.1 创建 sandbox-docker-compose.yaml

> 📖 **概念小课堂：什么是 docker compose？**
>
> 一个 Docker 容器只跑一个服务。如果一个项目要多个容器（比如 web + 数据库 + 缓存），手动 docker run 启动每个太麻烦。`docker compose` 用一个 YAML 文件声明所有容器，一条命令全启动。
>
> XiaoPaw 的沙箱是单容器，但用 compose 文件管理更清晰。

```yaml
# sandbox-docker-compose.yaml
# AIO-Sandbox：AI 代码执行的隔离容器

services:
  # ↑ services 是 compose 文件的顶级 key，下面定义所有服务
  aio-sandbox:
    # ↑ 服务名（自定义，叫什么都行，这里是 aio-sandbox）
    image: registry.cn-hangzhou.aliyuncs.com/aio/aio-sandbox:latest
    # ↑ image 指定用哪个镜像
    # ↑ registry.cn-hangzhou.aliyuncs.com 阿里云镜像仓库（国内拉取快）
    # ↑ aio/aio-sandbox 镜像名
    # ↑ :latest 标签（最新版，生产建议锁版本号）
    container_name: xiaopaw-aio-sandbox
    # ↑ 容器名（固定，方便后续 docker ps 找到它）
    ports:
      - "8030:8030"
      # ↑ 端口映射：宿主机端口:容器端口
      # ↑ 宿主机的 8030 端口转发到容器的 8030 端口
    volumes:
      # ↑ 卷挂载：把宿主机目录"挂"到容器里
      - ./xiaopaw/skills:/mnt/skills:ro
      # ↑ 格式：宿主机路径:容器路径:权限
      # ↑ ./xiaopaw/skills 项目里的技能目录
      # ↑ /mnt/skills 容器内的挂载点
      # ↑ :ro read-only 只读（沙箱不能改技能文件）
      - ./data/workspace:/workspace
      # ↑ 工作区目录挂载（可读写，沙箱要写记忆文件）
    environment:
      - WORKSPACE_DIR=/workspace
      # ↑ 给容器传环境变量，告诉它工作区在哪
    restart: unless-stopped
    # ↑ 重启策略：除非手动 stop，否则总是自动重启
    # ↑ 容器崩了会自动拉起来
```

```text 逐行解释
image: ...:latest
    拉镜像：从阿里云镜像仓库下载 aio-sandbox 镜像
    第一次会慢（几百 MB），后续启动秒级（用本地缓存）
ports: - "8030:8030"
    端口映射：你的电脑 8030 端口 ↔ 容器 8030 端口
    电脑访问 localhost:8030 = 访问容器内部 8030
volumes: - ./xiaopaw/skills:/mnt/skills:ro
    把项目的 skills 目录挂进容器
    :ro = read-only，容器只能读不能改（安全）
volumes: - ./data/workspace:/workspace
    工作区挂载，可读写
    沙箱在这里读写用户记忆文件
restart: unless-stopped
    容器崩了自动重启，除非你手动 docker stop
```

### 4.3 设置工作区权限（重要！）

> 📖 **概念小课堂：UID 和文件权限**
>
> Linux 系统里每个文件都有"主人"（UID）。沙箱容器以 `gem` 用户（UID 1000）运行，它要写 `data/workspace/` 里的文件。如果这个目录是宿主机 root 的，容器没权限写——会"假装"成功但实际写不进去。

沙箱容器以 `gem` 用户（UID 1000）运行，需要能写入工作区文件：

```bash
# Linux / macOS
chmod -R 777 data/workspace/
# ↑ chmod = change mode 修改权限
# ↑ -R recursive 递归（包括子目录和文件）
# ↑ 777 三组权限：所有者/组/其他，每组 rwx（读/写/执行）
# ↑ 7 = 4+2+1 = r+w+x，所有人都能读写执行
# ↑ 注意：777 不安全，开发环境用，生产用 chown 改属主

# Windows 不需要这步（NTFS 权限模型不同，默认可读写）
```

> ⚠️ **常见坑**：如果权限不对，memory-save 技能会"假装"成功但实际没写入，导致记忆丢失。这是项目里最坑的问题之一——表面看代码没报错，但用户记忆全没了。

## 五、启动 pgvector（可选）

> 📖 **概念小课堂：什么是向量数据库？**
>
> 你写"Python"，数据库怎么找类似的内容？传统数据库只能精确匹配。向量数据库把文本变成数学向量（一串数字），用"距离"衡量相似度——向量距离近 = 内容相似。pgvector 是 PostgreSQL 的向量扩展，让你用熟悉的 SQL 查相似内容。
>
> XiaoPaw 的三层记忆中第三层用向量搜索找历史对话。

如果需要三层记忆中的向量搜索功能，需要启动 PostgreSQL + pgvector：

```bash
# 用 Docker 快速启动 pgvector
docker run -d --name pgvector \
  -e POSTGRES_USER=xiaopaw \
  -e POSTGRES_PASSWORD=xiaopaw \
  -e POSTGRES_DB=xiaopaw \
  -p 5432:5432 \
  pgvector/pgvector:pg16
```

```text 逐行解释
docker run -d --name pgvector
    docker run   从镜像启动一个容器
    -d           detached 后台运行
    --name pgvector  给容器起名 pgvector（方便后续 docker stop pgvector）
-e POSTGRES_USER=xiaopaw
    -e 设置环境变量
    POSTGRES_USER 数据库用户名（postgres 镜像认这个变量初始化）
-e POSTGRES_PASSWORD=xiaopaw
    数据库密码（生产环境一定要改！）
-e POSTGRES_DB=xiaopaw
    自动创建的库名
-p 5432:5432
    端口映射：宿主机 5432 ↔ 容器 5432
    5432 是 PostgreSQL 默认端口
pgvector/pgvector:pg16
    镜像名：pgvector 组织 / pgvector 镜像 / pg16 标签（基于 PostgreSQL 16）
```

```bash

sleep 3

# 设置环境变量（告诉 XiaoPaw 数据库地址）
export MEMORY_DB_DSN="postgresql://xiaopaw:xiaopaw@localhost:5432/xiaopaw"
# ↑ DSN = Data Source Name 数据源名
# ↑ 格式：postgresql://用户名:密码@主机:端口/库名

# 创建表结构（后续会创建 schema.sql）
psql "$MEMORY_DB_DSN" -f schema.sql
# ↑ psql 是 PostgreSQL 命令行客户端
# ↑ "$MEMORY_DB_DSN" 用环境变量传连接串
# ↑ -f schema.sql 执行这个 SQL 文件创建表
```

✅ **验证成功**：`psql` 不报错
❌ **常见错误**：`psql: command not found` → 没装 psql 客户端。可以 `docker exec -it pgvector psql -U xiaopaw` 在容器内执行。

## ❓ 常见问题

**Q1：为什么每次打开终端都要重新激活虚拟环境？**

A：因为虚拟环境的激活只对当前 shell 生效——它本质是改了 PATH 环境变量，让 `python` 命令指向 `.venv` 里的解释器。新开的终端是新的 shell，PATH 是默认的，所以必须重新激活。嫌烦可以装 `direnv` 自动激活。

**Q2：我用 Python 3.10 行不行？**

A：不推荐。XiaoPaw 用了 3.11+ 才有的特性（比如 `ExceptionGroup`、性能优化）。3.10 可能能跑，但会有兼容性问题，遇到坑没人帮你查。

**Q3：Docker Desktop 在 Windows 上启动特别慢怎么办？**

A：分配资源不够。打开 Docker Desktop 设置 → Resources，把内存调到 4GB+，CPU 调到 2 核+。还要确保 WSL2 装好（`wsl --update` 更新一下）。

**Q4：pip install 一直卡在 downloading，怎么解决？**

A：换国内镜像源（清华、阿里、豆瓣都有）。临时用：`pip install -i https://pypi.tuna.tsinghua.edu.cn/simple 包名`。永久：`pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`。

**Q5：沙箱容器一直 Restarting 状态怎么办？**

A：看日志：`docker compose -f sandbox-docker-compose.yaml logs`。常见原因：1）端口被占用；2）挂载路径不对；3）镜像没拉下来（网络问题，配阿里云加速器）。

**Q6：我没有飞书开发者账号，能学吗？**

A：能。本项目提供 TestAPI（端口 9090）作为开发调试入口——用 `curl` 就能发消息测试，不依赖飞书。飞书集成是后面章节才学的内容，前面都可以用 TestAPI 调试。

**Q7：装完依赖 pip list 显示一堆我不认识的包，正常吗？**

A：正常。CrewAI 等核心包会带很多间接依赖（依赖的依赖）。只要核心包能 `import` 成功就行，不用管间接依赖。

**Q8：电脑装了多个 Python 版本，怎么指定用哪个？**

A：用 `pyenv`（跨平台）或 `py -3.11`（Windows Python Launcher）。也可以创建虚拟环境时指定解释器路径：`python3.11 -m venv .venv`。

```bash
# 测试 Docker 镜像仓库能不能拉
docker pull hello-world
# ↑ 拉个测试镜像，能拉说明网络通
```

**技巧 5：环境变量没生效怎么办**

```bash
# 验证环境变量
echo $QWEN_API_KEY   # macOS/Linux
echo $env:QWEN_API_KEY  # Windows PowerShell

# 如果输出空，说明没生效：
# - 检查是不是在当前 shell 设的（重开终端就丢）
# - 检查是不是在虚拟环境激活后才设的（影响范围）
# - 永久设置：写进 ~/.bashrc（Linux/Mac）或系统环境变量（Windows）
```

**技巧 6：彻底重装依赖**

```bash
# 删光虚拟环境重来（核武器级，慎用）
rm -rf .venv                # Linux/Mac
Remove-Item -Recurse .venv  # Windows PowerShell

# 重建
python -m venv .venv
.venv\Scripts\Activate.ps1   # Windows
pip install -e ".[full,dev]"
```
