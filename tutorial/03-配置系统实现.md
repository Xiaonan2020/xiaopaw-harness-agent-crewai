## 一、为什么需要配置系统？

### 📖 概念小课堂：什么是"配置"

**配置（Configuration）** 指的是程序运行时需要的外部参数，比如数据库地址、端口号、API 密钥、超时时间等。这些参数不像代码逻辑那样固定，而是会因环境（开发/测试/生产）不同而变化。

打个比方：配置就像厨房菜谱里的"调料用量"。同一道菜（程序逻辑）在家里做（开发环境）和家人聚餐（生产环境）用盐量不同，但做法一样。如果不写明用量，每次都"凭感觉加"，结果就难以预测。

### 1.1 本节学习目标

- 理解"参数写死"带来的三大危害
- 掌握"配置与代码分离"的设计思想
- 学会用反面示例判断代码质量

### 1.2 如果没有配置系统会怎样？

来看一个反面教材：参数全部写死在代码里。

```python
# ❌ 坏味道：参数写死在代码里
class FeishuListener:
    def __init__(self):
        self.app_id = "cli_xxxxx"      # 修改需要改代码
        self.app_secret = "xxxxx"      # 敏感信息泄露到代码仓库
        self.port = 8030               # 无法在不同环境使用不同值
```

这种写法有三大危害：

1. **修改成本高**：每次改端口号都要修改源码、重新打包、重新部署
2. **安全风险大**：App Secret 这种敏感信息一旦提交到 Git，泄露给所有有代码访问权限的人
3. **环境无法隔离**：开发用 8030 端口，生产用 8031 端口，无法切换

💡 **实际场景**：小明在公司开发时端口写死成 8030，结果上线时发现生产服务器 8030 已被占用。他不得不修改代码、重新打包、再次走发布流程，浪费 2 小时。

对比正确的设计：

```python
# ✅ 好设计：从配置传入参数
class FeishuListener:
    def __init__(self, app_id: str, app_secret: str):
        self.app_id = app_id           # 从配置传入，不写死
        self.app_secret = app_secret   # 敏感信息从环境变量注入
```

这里 `__init__` 接收参数，而不是自己写死。参数从哪里来？从配置系统来。

### 1.3 配置系统的三个目标

1. **类型安全**：启动时即校验配置值（端口必须是 1024-65535 的整数）
2. **环境隔离**：开发/测试/生产用不同配置，通过环境变量切换
3. **文档自解释**：配置文件本身就是文档，每个字段有默认值和约束

### 📖 概念小课堂：什么是"类型安全"

**类型安全（Type Safety）** 指程序在运行前（最好在启动时）就能发现类型错误。比如端口必须是整数，如果配置文件里写成了字符串 `"abc"`，类型安全的系统会在启动时报错，而不是运行到一半崩溃。

打个比方：上高铁前过安检，发现你带了违禁品（错误配置），马上拦下；而不是等你上车运行 5 小时后才出问题。

## 二、Pydantic 基础

### 2.1 本节学习目标

- 理解 Pydantic 的定位与作用
- 掌握 `BaseModel`、`Field` 两个核心 API
- 能写出一个简单的配置模型并校验

### 2.2 什么是 Pydantic？

📖 **概念小课堂**：**Pydantic** 是 Python 生态最流行的数据校验库，基于类型注解（type hints）自动校验数据。它被 FastAPI、LangChain 等知名项目使用。XiaoPaw 用它来校验配置，是因为它"声明即校验"，代码即文档。

**技术选型对比**：为什么不选其他方案？

| 方案 | 优势 | 劣势 | 适合场景 |
|------|------|------|---------|
| `dict` 直接读 YAML | 简单 | 无类型校验、无提示 | 临时脚本 |
| `dataclass` | 标准库自带 | 不支持嵌套校验、无默认值约束 | 简单数据结构 |
| **Pydantic** | 类型校验、嵌套模型、错误信息清晰 | 需要安装 | 配置系统、API 模型 |
| `attrs` + `cattrs` | 灵活 | 学习曲线陡 | 复杂结构转换 |

XiaoPaw 选 Pydantic 是因为配置项多、嵌套深、需要明确的校验错误信息。

### 2.3 第一个 Pydantic 模型

来看一个最小示例：

```python
from pydantic import BaseModel, Field

class ServerConfig(BaseModel):
    # ↑ 继承 BaseModel，Pydantic 会自动校验字段类型
    host: str = "127.0.0.1"
    # ↑ str 类型；默认值 "127.0.0.1"（本机地址）
    port: int = Field(default=8080, ge=1024, le=65535)
    # ↑ int 类型；Field() 添加校验规则
    # ↑ default=8080 表示默认端口
    # ↑ ge=1024 表示 >= 1024（避免系统保留端口）
    # ↑ le=65535 表示 <= 65535（端口上限）
    debug: bool = False
    # ↑ bool 类型；默认 False（生产环境关 debug）

# 创建实例时会自动校验
config = ServerConfig(host="0.0.0.0", port=9090, debug=True)
print(config.host)   # "0.0.0.0"
print(config.port)   # 9090

# 校验失败会抛出明确的错误
try:
    bad_config = ServerConfig(port=80)  # 80 < 1024，违反 ge=1024
except Exception as e:
    print(f"校验失败：{e}")
    # 输出会明确告诉你哪个字段、什么原因
```

**逻辑解释**：

- 第 3 行：`class ServerConfig(BaseModel)` 让类继承 Pydantic 的基类，自动获得校验能力
- 第 5 行：`host: str = "127.0.0.1"` 声明字段类型为字符串，默认值是本机地址
- 第 7 行：`port: int = Field(...)` 用 `Field()` 函数添加约束
  - `ge=1024`（greater than or equal）大于等于 1024
  - `le=65535`（less than or equal）小于等于 65535
- 第 11 行：`debug: bool = False` 布尔字段，默认关闭

### 2.4 Pydantic 核心概念速查表

| 概念 | 说明 | 示例 |
|------|------|------|
| `BaseModel` | 所有配置模型的基类，继承后自动校验 | `class Config(BaseModel)` |
| `Field()` | 字段约束，添加默认值、长度、范围等 | `Field(default=8080, ge=1024)` |
| `default_factory` | 可变默认值的工厂函数（避免共享引用） | `Field(default_factory=list)` |
| 嵌套模型 | 模型可以嵌套其他模型 | `class AppConfig` 包含 `FeishuConfig` |
| `ValidationError` | 校验失败抛出的异常，包含详细错误信息 | `try: ... except ValidationError` |
| 环境变量 | Pydantic Settings 支持自动读取环境变量 | `os.environ["PORT"]` |

📖 **概念小课堂：为什么用 `default_factory=list` 而不是 `default=[]`？**

Python 中函数默认参数只初始化一次，所有实例共享同一个列表对象，会导致"实例 A 修改了默认列表，实例 B 看到了"的诡异 bug。`default_factory=list` 每次创建实例时调用 `list()` 生成新列表，避免共享。

打个比方：办公室的共享白板（`default=[]`）每个人写的内容其他人都能看到；而 `default_factory=list` 相当于每人发一块新白板，互不干扰。

### 3.2 完整配置模型

以下是 `xiaopaw/config/validator.py` 的核心实现，每一行都加了注释：

```python
"""Pydantic 配置模型与启动时校验。"""
# ↑ 模块文档字符串，说明本文件作用

from pathlib import Path
# ↑ Path 用于跨平台路径操作（Windows/Linux 都能用）
from typing import Any
# ↑ Any 表示任意类型，用于 YAML 解析结果
import yaml
# ↑ PyYAML 库，用于读取 YAML 格式配置文件
from pydantic import BaseModel, Field
# ↑ BaseModel 是配置模型基类；Field 用于添加字段约束

from xiaopaw.config.flags import FeatureFlags
# ↑ 引入功能开关模型（稍后讲解）


# ── 飞书配置 ──────────────────────────────────────────────
class FeishuConfig(BaseModel):
    """飞书应用配置。"""
    # ↑ 类文档字符串，说明用途
    app_id: str = Field(min_length=8)
    # ↑ str 类型；Field(min_length=8) 表示至少 8 字符
    # ↑ 飞书 App ID 形如 "cli_xxxxx"，确实够长
    app_secret: str = Field(min_length=8)
    # ↑ App Secret 同样至少 8 字符，防止误填空值
    allowed_chats: list[str] = Field(default_factory=list)
    # ↑ list[str] 是字符串列表；default_factory=list 默认空列表
    # ↑ 用于配置允许机器人响应的群聊 ID（白名单机制）


# ── Agent 配置 ────────────────────────────────────────────
class AgentConfig(BaseModel):
    """Agent（智能体）配置。"""
    model: str = "qwen3-max"
    # ↑ LLM 模型名称；默认 qwen3-max（通义千问旗舰模型）
    max_iter: int = Field(default=50, ge=1, le=200)
    # ↑ 单轮最大迭代次数；范围 1-200
    # ↑ ge=1 至少迭代 1 次；le=200 最多 200 次（防止无限循环）
    max_input_tokens: int = Field(default=30000, ge=1000, le=128000)
    # ↑ 输入 token 上限；范围 1000-128000
    # ↑ 128000 是 qwen3-max 的上下文窗口上限
    sub_agent_model: str = "qwen3-max"
    # ↑ Sub-Crew（子智能体）使用的模型
    sub_agent_max_iter: int = Field(default=20, ge=1, le=100)
    # ↑ Sub-Crew 迭代上限，比主 Agent 小（节省成本）
    timeout_s: int = Field(default=300, ge=30, le=3600)
    # ↑ 整体超时时间（秒）；30s 到 1 小时
    llm_timeout_s: int = Field(default=120, ge=10, le=600)
    # ↑ 单次 LLM 调用超时；10s 到 10 分钟


# ── 沙箱配置 ──────────────────────────────────────────────
class SandboxConfig(BaseModel):
    """沙箱配置。"""
    url: str = "http://localhost:8030/mcp"
    # ↑ MCP（Model Context Protocol）端点地址
    # ↑ 默认本机 8030 端口
    timeout_s: int = Field(default=120, ge=10, le=600)
    # ↑ 沙箱执行超时；10s 到 10 分钟


# ── 记忆配置 ──────────────────────────────────────────────
class MemoryConfig(BaseModel):
    """三层记忆配置。"""
    db_dsn: str = ""
    # ↑ PostgreSQL 连接串；空字符串表示不启用向量搜索
    hard_limit_lines: int = 250
    # ↑ memory.md 文件最大行数；超过则触发压缩
    max_save_length: int = 2000
    # ↑ 单条记忆最大长度（字符数）
    compress_threshold: float = 0.45
    # ↑ 上下文压缩阈值；占比低于 45% 时触发压缩
    context_window_tokens: int = 32000
    # ↑ 上下文窗口大小（token 数）
    fresh_keep_turns: int = 10
    # ↑ 保留最近 10 轮对话不压缩（保证近期上下文完整）


# ── 会话配置 ──────────────────────────────────────────────
class SessionConfig(BaseModel):
    """会话管理配置。"""
    max_active_sessions: int = Field(default=1000, ge=1)
    # ↑ 最大并发会话数；至少 1
    max_history_turns: int = Field(default=20, ge=1)
    # ↑ 保留历史轮数；默认 20 轮


# ── Runner 配置 ───────────────────────────────────────────
class RunnerConfig(BaseModel):
    """消息调度器配置。"""
    max_queue_size: int = Field(default=10, ge=1, le=100)
    # ↑ 单个队列最大长度；范围 1-100
    # ↑ 太大会占内存，太小会频繁丢消息
    idle_timeout_s: float = Field(default=300.0, ge=10)
    # ↑ 空闲超时（秒）；默认 5 分钟无消息则 Worker 退出


# ── 发送器配置 ────────────────────────────────────────────
class SenderConfig(BaseModel):
    """消息发送器配置。"""
    max_retries: int = Field(default=3, ge=1, le=10)
    # ↑ 最大重试次数；范围 1-10
    retry_backoff: list[float] = Field(
        default_factory=lambda: [1.0, 2.0, 4.0]
    )
    # ↑ 重试退避时间列表（指数退避）
    # ↑ 第 1 次重试等 1s，第 2 次等 2s，第 3 次等 4s
    max_concurrent: int = Field(default=5, ge=1, le=20)
    # ↑ 最大并发发送数；范围 1-20


# ── 调试配置 ──────────────────────────────────────────────
class DebugConfig(BaseModel):
    """开发调试配置。"""
    enable_test_api: bool = False
    # ↑ 是否启用 TestAPI（开发用 HTTP 接口）
    # ↑ 默认关闭，生产环境必须关闭
    test_api_host: str = "127.0.0.1"
    # ↑ TestAPI 监听地址；默认仅本机访问
    test_api_port: int = Field(default=9090, ge=1024, le=65535)
    # ↑ TestAPI 端口
    test_api_token: str = ""
    # ↑ TestAPI 认证 Token；空表示不鉴权（仅开发）


# ── 可观测性配置 ──────────────────────────────────────────
class ObservabilityConfig(BaseModel):
    """可观测性配置。"""
    metrics_host: str = "0.0.0.0"
    # ↑ 指标服务监听地址；0.0.0.0 表示所有网卡
    metrics_port: int = Field(default=8090, ge=1024, le=65535)
    # ↑ Prometheus 指标端口
    log_json: bool = True
    # ↑ 是否输出 JSON 格式日志（便于日志系统解析）


# ── 限流配置 ──────────────────────────────────────────────
class RateLimitConfig(BaseModel):
    """限流配置。"""
    per_user_per_minute: int = Field(default=20, ge=1)
    # ↑ 每用户每分钟最大请求数；默认 20


# ── 防重放配置 ────────────────────────────────────────────
class ReplayCacheConfig(BaseModel):
    """防重放缓存配置。"""
    maxsize: int = Field(default=10000, ge=100)
    # ↑ 缓存最大条目数；至少 100
    ttl_sec: float = Field(default=300.0, ge=10)
    # ↑ TTL（Time To Live）过期时间；默认 5 分钟


# ── 定时任务配置 ──────────────────────────────────────────
class CronConfig(BaseModel):
    """定时任务配置。"""
    enabled: bool = True
    # ↑ 是否启用定时任务
    check_interval_s: float = Field(default=30.0, ge=5)
    # ↑ 检查间隔；至少 5 秒
    filelock_timeout_s: float = Field(default=10.0, ge=1)
    # ↑ 文件锁超时；防止多实例同时执行
    max_dlq_retries: int = Field(default=3, ge=0)
    # ↑ 死信队列（DLQ）最大重试次数


# ── 清理服务配置 ──────────────────────────────────────────
class CleanupConfig(BaseModel):
    """数据清理配置。"""
    enabled: bool = True
    # ↑ 是否启用自动清理
    session_ttl_days: int = Field(default=180, ge=1)
    # ↑ 会话保留 180 天
    trace_ttl_days: int = Field(default=30, ge=1)
    # ↑ 追踪数据保留 30 天
    raw_ttl_days: int = Field(default=30, ge=1)
    # ↑ 原始数据保留 30 天
    run_hour_utc: int = Field(default=3, ge=0, le=23)
    # ↑ UTC 3 点执行（避开业务高峰）


# ── 总配置 ────────────────────────────────────────────────
class AppConfig(BaseModel):
    """应用总配置 —— 组合所有子配置。"""
    workspace: str = "data/workspace"
    # ↑ 工作目录路径
    data_dir: str = "data"
    # ↑ 数据存储根目录
    feishu: FeishuConfig = Field(default_factory=lambda: FeishuConfig(
        app_id="placeholder", app_secret="placeholder"
    ))
    # ↑ 飞书配置；默认 placeholder，生产环境必须替换
    agent: AgentConfig = Field(default_factory=AgentConfig)
    # ↑ Agent 配置；使用 AgentConfig 的默认值
    sandbox: SandboxConfig = Field(default_factory=SandboxConfig)
    # ↑ 沙箱配置
    memory: MemoryConfig = Field(default_factory=MemoryConfig)
    # ↑ 记忆配置
    session: SessionConfig = Field(default_factory=SessionConfig)
    # ↑ 会话配置
    runner: RunnerConfig = Field(default_factory=RunnerConfig)
    # ↑ Runner 配置
    sender: SenderConfig = Field(default_factory=SenderConfig)
    # ↑ 发送器配置
    debug: DebugConfig = Field(default_factory=DebugConfig)
    # ↑ 调试配置
    observability: ObservabilityConfig = Field(default_factory=ObservabilityConfig)
    # ↑ 可观测性配置
    rate_limit: RateLimitConfig = Field(default_factory=RateLimitConfig)
    # ↑ 限流配置
    replay_cache: ReplayCacheConfig = Field(default_factory=ReplayCacheConfig)
    # ↑ 防重放配置
    cron: CronConfig = Field(default_factory=CronConfig)
    # ↑ 定时任务配置
    cleanup: CleanupConfig = Field(default_factory=CleanupConfig)
    # ↑ 清理配置
    feature_flags: FeatureFlags = Field(default_factory=FeatureFlags)
    # ↑ 功能开关
```

**逻辑解释**：

1. **分模块设计**：每个子配置（飞书、Agent、沙箱等）独立成类，职责单一
2. **嵌套组合**：`AppConfig` 把所有子配置组合起来，形成统一入口
3. **默认值兜底**：每个子配置都有 `default_factory`，即使 YAML 没写也能用默认值启动
4. **约束保护**：所有数值字段都有 `ge`/`le` 范围约束，防止配错

💡 **实际场景**：开发时只写飞书凭证即可启动，其他配置都用默认值。生产环境通过完整 YAML 覆盖所有字段。

### 3.3 配置加载函数详解

**`load_config(path: Path) → AppConfig`**

- **参数 `path`**：YAML 配置文件的路径（`Path` 对象）
- **返回值**：`AppConfig` 实例，包含所有配置
- **异常**：文件不存在抛 `FileNotFoundError`；校验失败抛 `ValidationError`
- **用法**：

```python
from pathlib import Path
from xiaopaw.config.validator import load_config

cfg = load_config(Path("config.yaml"))
print(cfg.feishu.app_id)  # 访问飞书配置
```

- **注意**：YAML 文件路径必须是绝对路径或相对于工作目录的路径；文件必须存在。

完整实现：

```python
def load_config(path: Path) -> AppConfig:
    """从 YAML 文件加载并校验配置。

    流程：
    1. 读取 YAML 文件
    2. 环境变量替换（${ENV_VAR} 语法）
    3. Pydantic 校验
    4. 返回 AppConfig 实例

    如果校验失败，Pydantic 会抛出 ValidationError，
    包含详细的字段路径和错误原因。
    """
    # ↑ 函数文档字符串，说明流程和异常行为

    if not path.exists():
        # ↑ 检查文件是否存在
        raise FileNotFoundError(f"config file not found: {path}")
        # ↑ 不存在则抛 FileNotFoundError，提示明确路径

    # 读取 YAML 文件，返回 dict
    raw: dict[str, Any] = yaml.safe_load(path.read_text(encoding="utf-8")) or {}
    # ↑ path.read_text() 读取文件内容
    # ↑ encoding="utf-8" 显式指定编码（Windows 默认 GBK，会乱码）
    # ↑ yaml.safe_load() 把 YAML 字符串解析为 dict
    # ↑ or {} 防止空文件返回 None

    # Pydantic 校验（不通过会抛 ValidationError）
    return AppConfig(**raw)
    # ↑ **raw 把 dict 解包为关键字参数
    # ↑ 等价于 AppConfig(feishu=..., agent=..., ...)
```

### 3.4 环境变量替换机制

📖 **概念小课堂**：**环境变量（Environment Variable）** 是操作系统级别的键值对，进程启动时可以读取。它最大的优势是"不写入文件"，因此适合存放密钥、Token 等敏感信息。

打个比方：环境变量像家里的"保险箱密码"——只在主人脑里（系统环境），不写在记事本（代码文件）里。

#### 替换流程图

```
┌─────────────────────────────────────────┐
│ config.yaml 文件内容                    │
│   feishu:                               │
│     app_id: "${FEISHU_APP_ID}"          │  ← 占位符
└──────────────┬──────────────────────────┘
               │ 读取文件
               ▼
┌─────────────────────────────────────────┐
│ expand_env_vars() 函数处理              │
│   匹配 ${...} 模式                      │
│   查找环境变量 FEISHU_APP_ID           │
└──────────────┬──────────────────────────┘
               │ 替换
               ▼
┌─────────────────────────────────────────┐
│ 最终的 dict                             │
│   feishu:                               │
│     app_id: "cli_a1b2c3d4e5f6g7h8"      │  ← 真实值
└──────────────┬──────────────────────────┘
               │ AppConfig(**raw)
               ▼
┌─────────────────────────────────────────┐
│ AppConfig 实例（Pydantic 校验通过）     │
└─────────────────────────────────────────┘
```

#### 替换函数实现

```python
# 实际的替换逻辑在 safety.py 中：
import os
# ↑ os 模块用于访问环境变量
import re
# ↑ re 模块用于正则表达式匹配

_ENV_PATTERN = re.compile(r"\$\{(\w+)\}")
# ↑ 编译正则：匹配 ${字母数字下划线} 模式
# ↑ \w+ 表示一个或多个字母数字下划线
# ↑ 括号 () 是捕获组，提取变量名

def expand_env_vars(value: str) -> str:
    """把 ${ENV_VAR} 替换为环境变量的值。

    参数:
        value: 可能包含 ${ENV_VAR} 的字符串

    返回:
        替换后的字符串；找不到环境变量则保留原样
    """
    def replacer(match):
        # ↑ 内部函数，处理每个匹配
        env_name = match.group(1)
        # ↑ match.group(1) 取捕获组内容（变量名）
        return os.environ.get(env_name, match.group(0))
        # ↑ os.environ.get() 读取环境变量
        # ↑ 第二参数是默认值：找不到则保留原样（match.group(0) 是整个匹配文本）

    return _ENV_PATTERN.sub(replacer, value)
    # ↑ sub() 用 replacer 函数替换所有匹配
```

**逻辑解释**：

- 第 4 行：预编译正则，提升性能（每次调用不用重新编译）
- 第 9-12 行：定义内部函数 `replacer`，处理每个匹配
- 第 13 行：找不到环境变量时保留 `${ENV_VAR}` 原样，便于排查

💡 **实际场景**：在 `config.yaml` 写 `app_id: "${FEISHU_APP_ID}"`，启动前 `export FEISHU_APP_ID=cli_xxx`，程序运行时会自动替换。

## 四、Feature Flags 实现

### 4.1 本节学习目标

- 理解 Feature Flags 的设计动机
- 掌握 XiaoPaw 中 8 个 flag 的用途
- 学会根据场景选择 flag

### 4.2 什么是 Feature Flags？

📖 **概念小课堂**：**Feature Flags（功能开关）** 是一种运行时控制功能启停的机制。把功能做成"开关"，可以在不重启程序的情况下打开/关闭某个功能。

打个比方：家里的总闸（程序）下挂了很多分开关（客厅灯、卧室灯、空调），关掉一个不影响其他。如果只有总闸，要关客厅灯就得全屋断电。

### 4.3 FeatureFlags 实现

```python
# xiaopaw/config/flags.py
from pydantic import BaseModel

class FeatureFlags(BaseModel):
    """功能开关 —— 运行时控制各功能模块的启停。"""
    # ↑ 继承 BaseModel，享受类型校验

    token_counter_mode: str = "rough"
    # ↑ Token 计数模式；"rough" 粗略估算，"precise" 精确计算
    enable_skill_timeout: bool = True
    # ↑ 技能超时控制；防止某个技能卡死整个 Agent
    enable_cron_filelock: bool = True
    # ↑ 定时任务文件锁；防止多实例重复执行
    enable_memory_save_filelock: bool = True
    # ↑ 记忆保存文件锁；防止并发写覆盖
    enable_trace_id: bool = True
    # ↑ 链路追踪 ID；开启后每条消息有唯一 ID 便于排查
    enable_mcp_whitelist: bool = True
    # ↑ MCP 工具白名单；只允许调用配置的工具
    enable_memory_save_filter: bool = True
    # ↑ 记忆保存过滤；过滤掉无意义内容（如纯表情）
    enable_webhook_replay_cache: bool = True
    # ↑ 防重放缓存；防止飞书重发消息导致重复处理
    enable_inbound_rate_limit: bool = True
    # ↑ 入站限流；防止用户刷屏
```

### 4.4 什么场景用哪个 flag？

| Flag | 适用场景 | 关闭后的影响 |
|------|---------|------------|
| `token_counter_mode="rough"` | 默认开发/测试，快速估算 | 切换 `precise` 后 CPU 占用升高，但计数准确 |
| `enable_skill_timeout=False` | 调试单个技能时不想被打断 | 技能卡死会拖垮整个会话 |
| `enable_cron_filelock=False` | 单实例部署 | 多实例会重复执行定时任务 |
| `enable_trace_id=False` | 性能压测（减少日志开销） | 出问题无法追踪单条消息 |
| `enable_mcp_whitelist=False` | 开发期测试新工具 | 任意工具可被调用，安全风险高 |
| `enable_webhook_replay_cache=False` | 调试重放逻辑时 | 同一消息可能被处理多次 |
| `enable_inbound_rate_limit=False` | 压测时需要大量请求 | 用户可刷屏，LLM 成本飙升 |

### 4.5 使用示例

```python
# 在代码中根据 flag 控制行为
if flags.enable_inbound_rate_limit:
    # ↑ 开启限流时执行
    if not rate_limiter.allow(sender_id):
        # ↑ 检查是否超限
        return "请求过于频繁，请稍后再试"

if flags.enable_trace_id:
    # ↑ 开启追踪时生成 ID
    trace_id = f"s-{uuid.uuid4().hex[:12]}"
    # ↑ s- 前缀表示 source（来源），后接 12 位 hex
```

💡 **实际场景**：上线后发现限流太严，可以在 `config.yaml` 改 `enable_inbound_rate_limit: false` 重启即可，不用改代码。

## 五、生产安全检查

### 5.1 本节学习目标

- 理解为什么生产环境需要额外检查
- 掌握三个必查项
- 学会区分开发模式与生产模式

### 5.2 为什么生产环境需要额外检查？

📖 **概念小课堂**：开发模式（dev）和生产模式（prod）的容忍度不同。开发时允许 placeholder 凭证、开 TestAPI、无鉴权；生产环境绝不允许，否则会被攻击。

打个比方：在自己家可以穿睡衣，但上台演讲必须穿正装。生产检查就是"出门前的镜子"。

### 5.3 安全检查函数详解

**`assert_all_production_safe(cfg: AppConfig, is_dev: bool = False) → None`**

- **参数 `cfg`**：要检查的配置实例
- **参数 `is_dev`**：是否开发模式；True 则跳过检查
- **返回值**：无（不通过则抛 `ValueError`）
- **用法**：

```python
from xiaopaw.config.safety import assert_all_production_safe

assert_all_production_safe(cfg, is_dev=False)  # 生产模式严格检查
```

- **注意**：必须在程序启动早期调用，配置加载之后、业务初始化之前。

完整实现：

```python
# xiaopaw/config/safety.py
def assert_all_production_safe(cfg: AppConfig, is_dev: bool = False):
    """生产环境启动前安全检查。

    在生产模式下（is_dev=False），必须满足：
    1. 飞书凭证不能是 placeholder
    2. TestAPI 必须关闭
    3. debug.test_api_token 必须为空或足够复杂
    """
    # ↑ 文档字符串明确三个检查项

    if is_dev:
        # ↑ 开发模式直接返回
        return  # 开发模式跳过检查

    # 检查飞书凭证
    if cfg.feishu.app_id == "placeholder":
        # ↑ 凭证仍是默认占位符
        raise ValueError("生产环境必须配置真实的飞书 App ID")
        # ↑ 直接抛异常，阻止启动

    # 检查 TestAPI
    if cfg.debug.enable_test_api:
        # ↑ TestAPI 开启了
        raise ValueError("生产环境不能启用 TestAPI")
        # ↑ TestAPI 暴露 HTTP 接口，攻击者可发任意消息

    # 检查 Token 强度
    if cfg.debug.test_api_token and len(cfg.debug.test_api_token) < 16:
        # ↑ Token 非空但长度不足 16
        raise ValueError("TestAPI Token 至少 16 字符")
        # ↑ 短 Token 易被暴力破解
```

**逻辑解释**：

1. 第 8-9 行：开发模式直接放行，避免本地开发被卡
2. 第 12-14 行：飞书凭证检查——防止上线后用默认值导致机器人无法工作
3. 第 17-19 行：TestAPI 检查——生产环境绝不能开 HTTP 调试接口
4. 第 22-24 行：Token 强度检查——防止用弱密码被破解

### 6.2 在 main.py 中加载配置

```python
# xiaopaw/main.py
from pathlib import Path
# ↑ Path 用于路径操作
import os
# ↑ os 用于读取环境变量
from xiaopaw.config.validator import load_config
# ↑ 导入配置加载函数

async def main():
    # 1. 确定配置文件路径（可通过环境变量覆盖）
    config_path = Path(os.environ.get("XIAOPAW_CONFIG", "config.yaml"))
    # ↑ 默认读 config.yaml；环境变量 XIAOPAW_CONFIG 可覆盖

    # 2. 加载并校验配置
    cfg = load_config(config_path)
    # ↑ 返回 AppConfig 实例

    # 3. 判断运行环境
    is_dev = os.environ.get("XIAOPAW_ENV", "dev") == "dev"
    # ↑ 默认 dev；设 XIAOPAW_ENV=prod 进入生产模式

    # 4. 生产环境安全检查
    assert_all_production_safe(cfg, is_dev=is_dev)
    # ↑ 生产模式严格检查；开发模式跳过

    # 5. 使用配置
    runner = Runner(
        idle_timeout=cfg.runner.idle_timeout_s,      # 从配置读取
        max_queue_size=cfg.runner.max_queue_size,
    )

    sender = FeishuSender(
        max_retries=cfg.sender.max_retries,
        retry_backoff=tuple(cfg.sender.retry_backoff),
        # ↑ list 转 tuple（不可变更安全）
    )
```

### 6.3 配置覆盖优先级

```
环境变量 > config.yaml > Pydantic 默认值

示例：
  Pydantic 默认值:  port = 9090
  config.yaml:      port = 9091          ← 覆盖默认值
  环境变量:          TEST_API_PORT=9092   ← 覆盖配置文件（需代码支持）
```

💡 **实际场景**：本地用 9090，公司测试服 9091，云上生产 9092。同一份代码，三套配置，互不影响。

## 七、设计优势与局限性

### 优势

1. **启动即失败**：配置错误在启动时就暴露，不会运行到一半崩溃
2. **类型提示**：IDE 能自动补全配置字段，减少拼写错误
3. **文档自解释**：每个字段有默认值和约束，配置文件即文档
4. **环境隔离**：通过环境变量实现不同环境不同配置

### 局限性

1. **不支持热更新**：修改配置需要重启服务
2. **嵌套较深**：`cfg.debug.test_api_port` 嵌套 2 层，可读性一般
3. **环境变量类型**：环境变量都是字符串，需要手动转换类型

## ❓ 常见问题

### Q1：启动时报 `ValidationError: field required`，怎么办？

**A**：Pydantic 提示某个字段必填但没有提供。检查 `config.yaml` 是否漏写字段。错误信息会明确指出是哪个字段，例如：

```
ValidationError: 1 validation error for FeishuConfig
app_id
  field required (type=value_error.missing)
```

补上 `feishu.app_id` 即可。

### Q2：环境变量替换不生效，`${FEISHU_APP_ID}` 还是原样？

**A**：检查三步：
1. 环境变量是否已 export：`echo $FEISHU_APP_ID` 应该有值
2. config.yaml 里写法是否正确：必须是 `"${FEISHU_APP_ID}"`（带引号、带 `$` 和 `{}`）
3. 启动程序的 shell 和 export 变量的 shell 是否一致

### Q3：生产环境启动报 `ValueError: 生产环境必须配置真实的飞书 App ID`？

**A**：你的 `XIAOPAW_ENV` 设成了 prod，但飞书凭证还是 `placeholder`。两种解决：
- 真上线：在 config.yaml 配置真实 App ID 和 Secret（用环境变量替换）
- 临时调试：把 `XIAOPAW_ENV` 改回 `dev`

### Q4：配置改了不生效？

**A**：Pydantic 配置不支持热更新，必须重启服务。如果你在容器里改了 yaml 但没重启容器，配置不会生效。

### Q5：`default_factory=lambda: FeishuConfig(app_id="placeholder", ...)` 为什么要用 lambda？

**A**：Pydantic 的 `default_factory` 接收一个可调用对象（函数）。如果直接写 `default=FeishuConfig(...)`，所有实例会共享同一个 FeishuConfig 对象（可变共享 bug）。用 lambda 包装，每次创建实例时调用 lambda 生成新对象。

### Q6：如何添加一个新的配置项？

**A**：三步：
1. 在对应的 Config 类里加字段（如 `AgentConfig` 加 `temperature: float = 0.7`）
2. 在 config.yaml 里加对应字段（可选，有默认值就不强制）
3. 在代码里通过 `cfg.agent.temperature` 读取

### Q7：config.yaml 必须放在哪里？

**A**：默认放在程序工作目录下。也可以通过环境变量 `XIAOPAW_CONFIG` 指定任意路径，例如 `XIAOPAW_CONFIG=/etc/xiaopaw/config.yaml`。

### Q8：YAML 文件里怎么写嵌套配置？

**A**：用缩进表示层级，例如：

```yaml
feishu:
  app_id: "${FEISHU_APP_ID}"
  app_secret: "${FEISHU_APP_SECRET}"
  allowed_chats:
    - "oc_chat1"
    - "oc_chat2"

agent:
  model: "qwen3-max"
  max_iter: 50
```

注意：YAML 用空格缩进，不能用 Tab；同级元素对齐。
