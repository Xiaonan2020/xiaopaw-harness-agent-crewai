## 一、生产环境部署

### 1.1 部署架构

```
┌───────────────────────────────────────────────────────┐
│  生产环境（开店营业后的"店铺后厨"）                     │
│                                                       │
│  ┌─────────────────┐    ┌─────────────────┐          │
│  │  XiaoPaw 主进程  │    │  AIO-Sandbox    │          │
│  │  (Python)       │◄──►│  (Docker)       │          │
│  │  端口: 8090     │    │  端口: 8030     │          │
│  │  (店长+前台)    │    │  (工具房)        │          │
│  └────────┬────────┘    └─────────────────┘          │
│           │                                           │
│  ┌────────▼────────┐    ┌─────────────────┐          │
│  │  PostgreSQL     │    │  Langfuse       │          │
│  │  + pgvector     │    │  (可观测)       │          │
│  │  端口: 5432     │    │  端口: 3000     │          │
│  │  (档案室)       │    │  (监控室)        │          │
│  └─────────────────┘    └─────────────────┘          │
│                                                       │
│  外部服务（水电煤，公用事业）：                       │
│  ├── 飞书开放平台 (WebSocket)        ← 收发消息       │
│  ├── 阿里云 DashScope (LLM API)      ← 大模型推理    │
│  └── 百度搜索 API (可选)             ← 搜索技能      │
└───────────────────────────────────────────────────────┘
```

**架构说明（生活类比）**：
- XiaoPaw 主进程 = 店长 + 前台，负责接单（飞书消息）、调度（Agent 编排）
- AIO-Sandbox = 工具房，需要执行命令时去那里
- PostgreSQL = 档案室，存记忆和会话历史
- Langfuse = 监控室，记录每笔"业务"的全过程
- 飞书/DashScope = 公用事业，需要交钱才能用

### 1.2 部署清单

| 组件 | 配置要求 | 端口 | 生活类比 |
|------|---------|------|---------|
| XiaoPaw | 2C4G+ | 8090 (metrics) | 店面 |
| AIO-Sandbox | 2C4G+ | 8030 (MCP) | 工具房 |
| PostgreSQL | 1C2G+ | 5432 | 档案室 |
| Langfuse | 1C2G+ | 3000 | 监控室 |

**最低硬件**：一台 8 核 16G 的服务器即可跑全套（建议 16 核 32G 给生产环境留余量）。

### 1.4 Docker Compose 生产部署（逐行注释）

```yaml
# docker-compose.prod.yaml
# 用 Docker Compose 一键启动所有组件

version: "3.8"                         # Compose 文件版本

services:                              # 定义所有服务
  xiaopaw:                             # 服务名：xiaopaw（主进程）
    build: .                           # 用当前目录的 Dockerfile 构建
    container_name: xiaopaw-prod       # 容器名（便于运维查找）
    restart: always                    # ★ 崩溃自动重启（生产必备）
    ports:
      - "8090:8090"                    # 暴露 metrics 端口到宿主机
    volumes:                           # 数据卷挂载（持久化）
      - ./data:/data                   # 数据目录映射（日志、向量索引）
      - ./config.prod.yaml:/app/config.yaml:ro  # 配置只读挂载（:ro = read only）
    environment:                       # 环境变量
      - XIAOPAW_ENV=production         # 标记当前是生产环境
      - QWEN_API_KEY=${QWEN_API_KEY}   # LLM API Key（从 .env 读取）
      - FEISHU_APP_ID=${FEISHU_APP_ID}  # 飞书 App ID
      - FEISHU_APP_SECRET=${FEISHU_APP_SECRET}  # 飞书 App Secret
      - MEMORY_DB_DSN=postgresql://xiaopaw:${DB_PASSWORD}@postgres:5432/xiaopaw  # DB 连接串
      - XIAOPAW_LANGFUSE_PUBLIC_KEY=${LANGFUSE_PUBLIC_KEY}  # Langfuse 公钥
      - XIAOPAW_LANGFUSE_SECRET_KEY=${LANGFUSE_SECRET_KEY}   # Langfuse 私钥
      - TRACE_TO_LANGFUSE=true         # 启用 trace 上报
    depends_on:                        # 依赖关系（启动顺序）
      - postgres                       # 先启动 postgres
      - sandbox                         # 再启动 sandbox
    healthcheck:                      # 健康检查（Docker 自动监控）
      test: ["CMD", "curl", "-f", "http://localhost:8090/metrics"]  # 检查命令
      interval: 30s                    # 每 30 秒检查一次
      timeout: 10s                     # 超时 10 秒算失败
      retries: 3                       # 连续失败 3 次标记 unhealthy

  sandbox:                             # 沙箱服务
    image: registry.cn-hangzhou.aliyuncs.com/aio/aio-sandbox:latest  # 阿里云镜像
    container_name: xiaopaw-sandbox    # 容器名
    restart: always                    # 自动重启
    ports:
      - "8030:8030"                    # MCP 端口
    volumes:
      - ./xiaopaw/skills:/mnt/skills:ro  # 技能目录只读挂载
      - sandbox-workspace:/workspace   # 工作区命名卷（持久化）
    deploy:                            # 部署配置（资源限制）
      resources:
        limits:                        # 资源上限（防止吃光宿主机）
          cpus: "2"                    # 最多用 2 个 CPU
          memory: 4G                   # 最多用 4GB 内存

  postgres:                            # 数据库服务
    image: pgvector/pgvector:pg16      # 带 pgvector 扩展的 Postgres 16
    container_name: xiaopaw-postgres
    restart: always
    ports:
      - "5432:5432"                    # DB 端口
    environment:
      - POSTGRES_USER=xiaopaw          # 数据库用户名
      - POSTGRES_PASSWORD=${DB_PASSWORD}  # 密码（从 .env 读取）
      - POSTGRES_DB=xiaopaw            # 默认数据库名
    volumes:
      - postgres-data:/var/lib/postgresql/data  # 数据持久化
      - ./schema.sql:/docker-entrypoint-initdb.d/schema.sql:ro  # 初始化 SQL（首次启动执行）

volumes:                               # 命名卷定义
  sandbox-workspace:                   # 沙箱工作区卷
  postgres-data:                       # Postgres 数据卷
```

#### Docker Compose 概念解释（小白先看这里）

| 概念 | 含义 |
|------|------|
| `services` | 定义要启动哪些容器（每个 service 一个容器） |
| `image` | 用什么镜像（如 `pgvector/pgvector:pg16`） |
| `build` | 用本地 Dockerfile 构建镜像 |
| `ports` | 端口映射，格式 `宿主机端口:容器端口` |
| `volumes` | 数据卷，把宿主机目录或命名卷挂到容器里 |
| `environment` | 环境变量，容器内能读到 |
| `depends_on` | 启动顺序依赖（A depends_on B 表示先启动 B） |
| `healthcheck` | 健康检查，Docker 会定期探活 |
| `restart: always` | 容器崩了自动重启 |
| `:ro` | 只读挂载，容器内不能修改 |

## 二、性能优化

### 2.1 异步并发优化（连接池 + 批量）

```python
# 1. 使用连接池减少连接开销
# 生活类比：不去 ATM 每次排队，办一张信用卡随身带
import aiohttp

# 全局连接池（复用 TCP 连接）
connector = aiohttp.TCPConnector(
    limit=100,            # 最大连接数（同时最多 100 个 HTTP 请求）
    limit_per_host=10,    # 每个主机最大连接（同一域名最多 10 个并发）
    ttl_dns_cache=300,    # DNS 缓存 300 秒（避免每次请求都查 DNS）
)
session = aiohttp.ClientSession(connector=connector)
# 优化前：每次请求都新建 TCP 连接（~100ms 开销）
# 优化后：连接复用，几乎 0 开销


# 2. 批量操作减少 IO 次数
async def batch_index_turns(turns: list, db_dsn: str):
    """批量索引多轮对话，减少数据库写入次数。"""
    # 优化前：循环里一条条 INSERT，10 轮 = 10 次数据库往返
    # 优化后：一次性 executemany，10 轮 = 1 次数据库往返
    conn = await asyncpg.connect(db_dsn)
    try:
        await conn.executemany(
            "INSERT INTO memory_vectors (session_id, embedding) VALUES ($1, $2)",
            [(t.session_id, t.embedding) for t in turns]  # 批量参数
        )
    finally:
        await conn.close()
```

| 优化项 | 优化前 | 优化后 | 提升幅度 |
|-------|--------|--------|---------|
| HTTP 连接 | 每次新建（100ms） | 复用（~1ms） | 100x |
| DB 写入 | 10 轮 10 次往返 | 10 轮 1 次往返 | 10x |

### 2.4 上下文优化

```python
# 更激进的剪枝策略
# 生活类比：会议纪要只记重点，不逐字记录
def aggressive_prune(messages: list, max_tokens: int = 16000):
    """激进剪枝 —— 保留更少的历史。"""
    # 优化前：max_tokens=32000，保留全部历史
    # 优化后：max_tokens=16000，砍掉一半历史
    # 牺牲少量上下文 → 节省一半 token 成本
    while estimate_tokens(messages) > max_tokens:
        # 删除最早的非 system 消息（保留 system prompt）
        for i, msg in enumerate(messages):
            if msg.get("role") != "system":
                messages.pop(i)
                break
```

| 优化项 | 优化前 | 优化后 | 提升幅度 |
|-------|--------|--------|---------|
| 上下文 token | 32000 tokens | 16000 tokens | 成本减半 |

## 三、安全增强

### 3.1 敏感信息保护

```python
# 1. 环境变量管理（不写入代码/配置文件）
# .env 文件（不入 git，要加到 .gitignore）
# .gitignore:
# .env           # 环境变量文件
# config.yaml    # 本地配置

# 2. PII 脱敏（Personally Identifiable Information，个人身份信息）
# xiaopaw/observability/pii_mask.py
import re

_PII_PATTERNS = [
    (re.compile(r'\b\d{18}\b'), '[ID]'),           # 18 位身份证号 → [ID]
    (re.compile(r'\b1[3-9]\d{9}\b'), '[PHONE]'),   # 11 位手机号 → [PHONE]
    (re.compile(r'\b[\w.]+@[\w.]+\b'), '[EMAIL]'),  # 邮箱 → [EMAIL]
]

def mask_pii(text: str) -> str:
    """脱敏 PII 信息。
    用途：日志里可能出现用户输入，需要先脱敏再写日志。"""
    for pattern, replacement in _PII_PATTERNS:
        text = pattern.sub(replacement, text)
    return text

# 脱敏前：日志里出现 "用户输入：我的手机号是 13800138000"
# 脱敏后：日志里出现 "用户输入：我的手机号是 [PHONE]"
```

### 3.2 网络安全

```python
# 限制沙箱网络访问
# docker-compose.prod.yaml
services:
  sandbox:
    # 内部网络，不暴露公网
    networks:
      - internal
    # 不映射端口到宿主机（注释掉 ports）
    # ports:
    #   - "8030:8030"  # 注释掉 → 外网访问不到沙箱

networks:
  internal:
    internal: true  # 完全隔离的内部网络（不能访问外网）
```

**攻击场景 → 防护措施对比**：

| 攻击场景 | 危害 | 防护措施 |
|---------|------|---------|
| 攻击者从外网访问沙箱 | 沙箱被滥用执行恶意代码 | 不映射端口 + 内部网络 |
| 攻击者用沙箱访问外网 | 沙箱变肉鸡、扫描内网 | `internal: true` 隔离 |
| 攻击者从沙箱访问 DB | 偷取记忆/会话数据 | 沙箱和 DB 不在同一网络 |
| 日志泄露用户 PII | 用户手机号/身份证被泄露 | mask_pii 脱敏 |

### 3.3 凭证隔离

```python
# 不同用户使用不同飞书凭证（多租户场景）
# 生活类比：每个客户用独立的保险箱，互不知道密码
class CredentialManager:
    """凭证管理器 —— 按用户隔离凭证。"""

    def __init__(self):
        self._credentials: dict[str, dict] = {}  # user_id → credentials

    def get_credentials(self, user_id: str) -> dict:
        """获取用户专属凭证。"""
        return self._credentials.get(user_id, {})

    def set_credentials(self, user_id: str, credentials: dict):
        """设置用户凭证。"""
        self._credentials[user_id] = credentials
```

### 3.4 审计强化

```python
# 审计日志加密
# 生活类比：账本用密码锁锁起来，防止被偷看
from cryptography.fernet import Fernet

class EncryptedAuditLogger:
    """加密审计日志器。
    用途：审计日志可能包含敏感信息，加密后即使文件泄露也无法读取。"""

    def __init__(self, key: bytes):
        # key 是 32 字节 base64 编码的密钥
        self._cipher = Fernet(key)

    def write(self, event: dict):
        """加密后写入审计日志。"""
        # 加密：明文 → 密文（不可逆，除非有 key）
        encrypted = self._cipher.encrypt(
            json.dumps(event).encode()
        )
        with open(self._log_file, "ab") as f:  # 二进制追加模式
            f.write(encrypted + b"\n")          # 每条记录一行
```

## 四、可扩展性提升

### 4.1 水平扩展方案

```
当前架构（单机，一家店）：
  单个 XiaoPaw 进程处理所有消息
  → 用户量上 1000+ 时单机会卡

水平扩展方案（连锁店）：
  ┌──────────────┐
  │  负载均衡器    │   ← 接待所有顾客，分流到各分店
  └──────┬───────┘
         │
    ┌────┼────┐
    ▼    ▼    ▼
  ┌─┐ ┌─┐ ┌─┐
  │P1│ │P2│ │P3│  多个 XiaoPaw 实例（多家分店）
  └─┘ └─┘ └─┘
    │   │   │
    └───┼───┘
        ▼
  ┌──────────┐
  │  Redis    │  共享 Session 状态（连锁店共享会员系统）
  │  (会话)   │
  └──────────┘
```

### 4.2 Redis 会话存储

```python
# 扩展 SessionManager 支持 Redis
import redis.asyncio as redis

class RedisSessionManager:
    """Redis 支持的会话管理器（水平扩展）。"""

    def __init__(self, redis_url: str):
        self._redis = redis.from_url(redis_url)

    async def get_or_create(self, routing_key: str) -> Session:
        """获取或创建会话。
        优化前：内存字典存 session，重启丢失，多实例不共享
        优化后：Redis 存 session，重启不丢，多实例共享"""
        key = f"session:{routing_key}"
        session_id = await self._redis.get(key)

        if session_id:
            # 已有会话，直接复用（即使请求到另一个实例也能命中）
            return Session(id=session_id.decode(), routing_key=routing_key, ...)

        # 新会话
        session = Session(id=str(uuid.uuid4())[:12], ...)
        await self._redis.setex(key, 86400, session.id)  # 24h TTL
        return session
```

### 4.3 消息队列解耦

```python
# 用 RabbitMQ/Kafka 替代内存队列
import aio_pika

class MQRunner:
    """基于消息队列的 Runner（支持多实例消费）。
    优化前：内存队列，单实例消费
    优化后：MQ，多实例可以同时消费（提高吞吐）"""

    async def dispatch(self, inbound: InboundMessage):
        connection = await aio_pika.connect_robust("amqp://localhost")
        async with connection:
            channel = await connection.channel()
            await channel.default_exchange.publish(
                aio_pika.Message(body=json.dumps(inbound).encode()),
                routing_key=f"messages.{inbound.routing_key}",
            )
```

### 5.1 Prometheus + Grafana 概念（小白先看这里）

### 5.3 告警规则（什么指标 → 什么阈值 → 什么告警）

```yaml
# prometheus.yml
# 告警系统配置
alerting:
  alertmanagers:                     # 告警分发器地址
    - static_configs:
        - targets: ['alertmanager:9093']

rule_files:                          # 告警规则文件
  - alerts.yml

# alerts.yml
# 告警规则定义
groups:
  - name: xiaopaw                    # 告警组名
    rules:
      # 告警 1：延迟过高
      - alert: HighLatency
        expr: histogram_quantile(0.95, xiaopaw_agent_latency_seconds_bucket) > 30
        # expr = 表达式：P95 延迟 > 30 秒
        # P95 = 95% 的请求延迟都低于这个值
        for: 5m                      # 持续 5 分钟才告警（避免抖动）
        annotations:
          summary: "Agent 延迟超过 30 秒"  # 告警内容

      # 告警 2：拦截率异常
      - alert: HighGuardrailDeny
        expr: rate(xiaopaw_guardrail_deny_total[5m]) > 0.1
        # expr = 表达式：5 分钟内 deny 速率 > 0.1 次/秒
        # 0.1 次/秒 = 每分钟 6 次拦截
        for: 2m                      # 持续 2 分钟
        annotations:
          summary: "安全拦截率高，可能有攻击"

      # 告警 3：沙箱宕机
      - alert: SandboxDown
        expr: up{job="sandbox"} == 0
        # expr = 表达式：沙箱 up 指标 = 0（不在线）
        for: 1m                      # 持续 1 分钟
        annotations:
          summary: "沙箱服务不可用"
```

#### 告警规则汇总表

| 告警名 | 监控指标 | 阈值 | 持续时间 | 含义 |
|--------|---------|------|---------|------|
| HighLatency | P95 延迟 | > 30s | 5min | Agent 响应慢 |
| HighGuardrailDeny | deny 速率 | > 0.1/秒 | 2min | 可能有攻击 |
| SandboxDown | up 指标 | == 0 | 1min | 沙箱挂了 |

## 八、设计优势与局限性

### 优势

1. **容器化部署**：Docker Compose 一键启动，环境一致
2. **安全加固**：9 个策略 + 网络隔离 + 凭证管理 + 审计加密
3. **可观测**：Metrics + Trace + 日志三位一体
4. **可扩展**：Redis/MQ 方案支持水平扩展

### 局限性

1. **单机瓶颈**：默认单实例，需要改造才能水平扩展
2. **LLM 依赖**：Qwen API 故障 = 服务不可用（需要降级方案）
3. **成本不可控**：LLM 调用按量计费，需要 cost_guard 围栏
4. **运维复杂**：多个组件需要分别维护（XiaoPaw + 沙箱 + DB + Langfuse）

## ❓ 常见问题

### Q1：Docker Compose 启动报 `port is already allocated`？
**A**：端口被占用。**排查**：
```bash
# 看哪个进程占了 8090
netstat -tlnp | grep 8090        # Linux
lsof -i :8090                    # Mac

# 解决方案：
# 1. 停掉占用进程
# 2. 或者改 docker-compose.prod.yaml 的端口映射（如 8091:8090）
```

### Q2：容器启动后立刻退出？
**A**：可能是配置错误。**排查**：
```bash
# 看容器日志
docker logs xiaopaw-prod

# 常见原因：
# 1. config.prod.yaml 路径不对 → 检查 volumes 挂载
# 2. 环境变量没设 → 检查 .env 文件
# 3. 数据库连不上 → 检查 postgres 是否启动
```

### Q3：飞书收不到消息？
**A**：可能原因：
1. 飞书应用配置错误（app_id/app_secret）
2. WebSocket 连接失败（看日志有没有 `websocket connected`）
3. 飞书事件订阅没开
**排查**：`docker logs xiaopaw-prod | grep feishu`

### Q4：沙箱调用一直超时？
**A**：可能原因：
1. 沙箱容器没启动（`docker ps` 看是否 Up）
2. 沙箱内部进程卡死（重启沙箱）
3. 网络不通（在 xiaopaw 容器里 ping sandbox）
**修复**：
```bash
docker compose -f docker-compose.prod.yaml restart sandbox
```

### Q5：LLM 调用报 401 Unauthorized？
**A**：API Key 错误或过期。**排查**：
```bash
# 检查环境变量是否注入
docker exec xiaopaw-prod env | grep QWEN

# 测试 API Key 是否有效
curl -H "Authorization: Bearer $QWEN_API_KEY" \
  https://dashscope.aliyuncs.com/api/v1/services/aigc/text-generation/generation
```

### Q6：PostgreSQL 连接报 `password authentication failed`？
**A**：密码不对。**排查**：
1. 检查 `.env` 里 `DB_PASSWORD` 是否和初始化时一致
2. 检查 `MEMORY_DB_DSN` 里的密码是否和 `DB_PASSWORD` 一致
3. 如果忘了密码，删掉 postgres-data 卷重新初始化（会丢数据！）

### Q7：内存持续增长怎么办？
**A**：可能内存泄漏。**排查**：
```bash
# 看内存曲线
docker stats xiaopaw-prod

# 进容器看 Python 对象
docker exec -it xiaopaw-prod python -c "
import gc
import objgraph
objgraph.show_most_common_types(limit=10)
"
# 看哪个类型的对象最多
```

### Q8：怎么回滚到上一个版本？
**A**：
```bash
# 1. 停掉当前服务
docker compose -f docker-compose.prod.yaml down

# 2. 切到上一个版本
git checkout v1.0.0  # 假设上个版本打了 tag

# 3. 重新构建启动
docker compose -f docker-compose.prod.yaml build
docker compose -f docker-compose.prod.yaml up -d
```
